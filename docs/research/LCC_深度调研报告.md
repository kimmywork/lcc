# 0. 一页速览

**核心诊断**：你们的瓶颈已经不在 finder，也不主要在形状分类器，而在**"模块 → GF(256) 符号 → RS 预算"这条链路的结构性失配**，以及**帧间异质性被平均指标掩盖**。

**最值得做的三件事**

1. **S1｜把硬判决 RS 换成"擦除 + 软判决 + CRC32 列表选择"，并同步审计打包方式。**  
   这是唯一能在**不增加任何模型算力**的前提下把可容忍模块错误率提升 3–7 倍的杠杆。【解析+本地实验】单次 errors-and-erasures RS 解码 ≈1.3 万 GF(256) 乘加，扫 32 档擦除 ≈0.42 M GF-op；而 width8 CNN 一帧要 1251 M MAC。**RS 软判决比 CNN 便宜约 3000 倍。**
2. **S2｜把形状层模型从 CNN 换成"C 实际残差上训练的线性/结构化判别器"。**  
   本地代理实验里，投影特征 + 线性判别（1.6 k MAC/模块）与低秩白化 + 类均值（9.5 k MAC/模块）在中等退化上比解析模板 NCC 高 **+26 ～ +36 个百分点**，而算力是 width8 CNN 的 **1/245 ～ 1/41**。这直接解决"平均慢 1.5×"的问题。
3. **S3｜建立"失败帧强制对齐 + 每帧 RS 预算占用"的数据与指标闭环。**  
   你们现在的训练集只覆盖"能走到数据模块"的帧，指标只看平均模块准确率。本地拟合表明：**平均 96.1% 与端到端 57.5% 完全自洽**，只要帧间错误率分布是重尾的（中位 1.18%、p90 11.7%）。优化平均准确率是在优化错误的统计量。

**明确不做**：finder 大网兜底、像素级 SR（任何训练域）、diffusion/flow 去模糊、默认走 WebGPU/WebNN、模块级 Transformer/SSM、纯学习端到端单应性、依赖 ONNX Runtime 的一切。理由见第 7 节。

## 1.2 三件事的具体形态

### S1｜RS 侧（零模型算力，最高杠杆）
- 输出**每模块可靠度**（不只是 argmax），融合几何/模糊/颜色/分类 margin 四路信号；
- RS 从"errors-only"改为 **errors-and-erasures**，用 **GMD/Chase 式多档擦除扫描 + CRC32 作为列表选择器**；
- 同步审计 **每个 GF(256) 符号涉及多少个不同模块（记作 s）**，以及 RS 块长；
- 预期：在**不改分类器**的情况下，把"刚好超预算"的帧救回来。真实照片 4/13 里若有 2–3 张是"差几个符号"，这是最便宜的救回路径。【推测，需 protocol E1 验证】

### S2｜形状层（把 CNN 换成线性/结构化判别器）
- 用你们已经导出的 367,755 个 **C 实际残差**，训练：
  - **投影特征（Radon-lite）+ 线性分类器**：~1.6 k MAC/模块；
  - **低秩白化 + 可学习类模板（判别式度量）**：~9.5 k MAC/模块；
- 两者都能纯 int8 + 基线 WASM SIMD 实现，无需 relaxed SIMD；
- 预期：模块级不低于 width8 的 96.1%，**单模块耗时降到 1/40 ～ 1/200**，从而**可以默认开启**而不是可选层。

### S3｜数据与指标（把"平均准确率"换成"预算占用分布"）
- 失败帧**强制对齐**（用已知 payload 反推真值网格）后导出残差，补齐训练集缺失的难尾；
- 主指标改为 **每帧 RS 预算占用 `U = (e + 2·t_used)/(n−k)`** 的分布 + `P(U ≤ 1)`；
- 辅以置信度校准指标（ECE、错误检测 AUC、risk–coverage），因为**擦除解码的收益完全由置信度判别力决定**（见 2.4）。

## 1.3 明确不做（详见第 7 节）
finder 大网、像素 SR、diffusion、WebGPU/WebNN 默认路径、模块级 Transformer/Mamba、端到端单应性回归、ONNX Runtime、继续压 width 到 4 以下而不先换算子。

# 2. 诊断：把你们给的数字算到底

> 本节全部是【解析】或【本地实验】，脚本随报告交付。**假设写在每张表下面，你们可以直接代入真实数字重算。**

## 2.1 最重要的一张表：3 bit/模块 与 GF(256) 的打包失配

【本地实验：`packing_tradeoff.py`】归一化到 1000 个形状模块（=3000 bit 净载荷），RS(255,223)，判据 `e + 2·rem ≤ n−k`：

| 打包方案 | 符号数 | 总 bit | 容量倍数 | **可容忍模块错误率** | **可容忍模块擦除率** |
|---|---|---|---|---|---|
| A 比特流直切字节（最可能的现状） | 375 | 3430 | 1.14× | **1.71%** | 3.42% |
| A′ 24 bit 组对齐（8 模块=3 符号） | 375 | 3430 | 1.14× | **1.88%** | 3.76% |
| B 比特流 + 短块 RS(64,32) | 375 | 6000 | 2.00× | **6.82%** | 13.64% |
| C 一模块=一符号（取值限 0..7） | 1000 | 9148 | 3.05× | **6.27%** | 12.55% |
| D 一模块=一符号 + RS(64,32) | 1000 | 16000 | 5.33× | **25.00%** | 50.00% |

**假设**：A 中一个 3 bit 模块平均触及 1.375 个字节（3 bit 落在 8 bit 边界上的期望）；A′ 中 8 个模块里有 2 个跨界，故 1.25；C/D 中模块与符号一一对应。

**读法（这是全报告最重要的结论）**：
- 你们当前 C 的模块错误率是 **8.70%**，width8 是 **3.90%**，width16 是 **3.00%**。
- 如果现状是打包 A，**可容忍上限只有 1.71%** —— 也就是说**任何分类器单靠自己都不可能把难帧推过门槛**，能解出来的帧必然是那些错误率远低于平均值的帧。
- **A→A′ 完全免费**（只改打包顺序），+10% 容忍度。
- **A→C：总比特变为 A 的 2.67 倍（3430→9148），换来 3.7× 的错误容忍度与 3.7× 的擦除容忍度**；在难信道下这个交换几乎肯定值得。
- **C 还有一个白送的好处**：符号取值被限制在 0..7，任何解出 >7 的数据符号都是**确定性的错误检测**，可以直接转成擦除或用于列表剪枝。【解析】

> ⚠️ 我不知道你们实际的打包与块长。**这是 protocol E0（半天工作量）要做的第一件事**：统计每个 RS 符号涉及的不同模块数直方图，以及每块的 n、k。如果实测 s≈1 且块很短，本节结论要按实测重算——但结论的**方向**（预算优先于准确率）不变。

## 2.2 模块准确率 → 块可解率（纯硬判决）

【本地实验：`rs_budget_model.py`】RS(255,223)，t=16，iid 近似，s = 每符号涉及的不同模块数：

| 模块准确率 | 模块错误率 | s=1 | s=2 | s=3 |
|---|---|---|---|---|
| 91.3%（当前 C） | 8.70% | **9.93%** | 0.00% | 0.00% |
| 94.0% | 6.00% | 63.72% | 0.29% | 0.00% |
| 96.1%（width8） | 3.90% | **97.66%** | 24.49% | 0.50% |
| 97.0%（width16） | 3.00% | 99.80% | 66.01% | 9.62% |
| 98.0% | 2.00% | 100.00% | 97.35% | 66.75% |
| 99.0% | 1.00% | 100.00% | 100.00% | 99.82% |

块长的影响（同样 t=16，冗余率不同）：

| RS(n,k) | 冗余率 | p=3.9%,s=1 | p=3.9%,s=2 | p=3.9%,s=3 | p=8.7%,s=3 |
|---|---|---|---|---|---|
| (255,223) | 12.5% | 97.66% | 24.49% | 0.50% | 0.00% |
| (128,96) | 25.0% | 100.00% | 98.17% | 72.94% | 0.10% |
| (64,32) | 50.0% | 100.00% | 100.00% | 99.94% | **64.65%** |

**结论**：s 和块长对端到端的影响**大于** 2–3 个点的模块准确率。这是"不要假设更大模型更好"的最硬证据。

## 2.3 为什么 96.1% 只换来 57.5%：帧间异质性

【本地实验：`heterogeneity_fit.json`】设每帧模块错误率 `p ~ Beta(a,b)`，均值固定为 3.9%。求解"多少异质性才能让 57.5% 的帧低于 1.88% 阈值"：

- 拟合结果 **Beta(a=0.319, b=7.855)**，`P(p ≤ 1.88%) = 0.576`（目标 0.575）
- 该分布的分位数：**p10=0.01%，p25=0.14%，p50=1.18%，p75=4.92%，p90=11.73%**

**这是一个可立即证伪的预测**：如果你们把 180 个能走到数据模块的 blur_shape 帧逐帧统计模块错误率，应该看到**中位数约 1%、p75 约 5%、p90 约 12%** 的重尾分布，而不是集中在 3.9% 附近。

**如果预测成立，直接推论**：
1. **平均模块准确率是错误的优化目标**。应该优化 `P(U ≤ 1)`，即预算占用不超支的帧比例。
2. 收益集中在 **p 落在 2%–8% 的那一段帧**（大约 25–35% 的帧）。这段帧只需要"少错 5–15 个模块"就能翻盘 —— **擦除解码正好干这件事**。
3. 对 p>15% 的帧（约 5–10%），任何模块级手段都无效，**必须早停**，不要在上面跑模型（这直接回答 D5）。

## 2.4 擦除的上界，以及"置信度判别力"才是真瓶颈

【本地实验：`rs_budget_model.py`】RS(255,223)，s=1：

| 模块准确率 | 纯硬判决 | **完美擦除（oracle 上界）** |
|---|---|---|
| 91.3% | 9.93% | **98.56%** |
| 96.1% | 97.66% | 100.00% |
| 97.0% | 99.80% | 100.00% |

**oracle 擦除在 91.3% 时就把 9.9% 拉到 98.6%** —— 擦除的信息论价值远超再提几个点准确率。但 oracle 不可得，现实取决于置信度能多好地把错误排到前面。蒙特卡洛（3000 次/点，GMD 扫 e∈{8,12,16,20,24,28,32}，完美 CRC 选择）：

| 模块准确率 | shift=0（无信息） | 0.7（AUC≈.70） | 1.0（≈.76） | 1.5（≈.86） | 2.0（≈.92） | 3.0（≈.98） |
|---|---|---|---|---|---|---|
| 91.3% | 10.5% | 10.2% | 10.8% | 15.1% | **29.9%** | **73.6%** |
| 96.1% | 97.1% | 98.3% | 97.7% | 98.4% | 99.4% | 100.0% |
| 97.0% | 99.7% | 99.9% | 99.6% | 99.8% | 99.9% | 100.0% |

（置信度模型：正确符号 conf~N(0,1)，错误符号 conf~N(−shift,1)。）

**关键结论**：
- **AUC < 0.8 的置信度对擦除解码几乎无用**（10.5%→10.8%）。
- 要有实质收益需要 **AUC ≳ 0.92**。
- 而我的代理实验显示：**在强退化下，廉价分类器的 margin 判别力恰恰崩到接近随机**（见 2.7 的 cap@10% 列）。
- ⇒ **可靠度不能只来自分类器 margin**，必须融合几何重投影残差、局部模糊估计、颜色拟合残差、邻域一致性。这是 P3 的全部动机，也是我认为你们最容易低估的一环。

## 2.5 成本不对称：这是"先做 RS 后做模型"的决定性论据

【本地实验：`rs_budget_model.py` 段 F】
- 单次 errors-and-erasures RS(255,223) 解码（BM + Chien + Forney）≈ **13,008 次 GF(256) 乘加**
- 扫 32 档擦除 ≈ **0.42 M GF-op**
- width8 CNN 一帧（v10，3249 模块 × 0.385 M MAC）= **1251 M MAC**

**比值 ≈ 3000×**（两者都是「基本乘加次数」量级的比较；GF(256) 乘加含一次查表，实际常数略大于 int8 MAC，但不改变数量级结论）。 即使 GMD 扫 32 档、每档对 8 个块各解一次，也才 3.4 M GF-op，仍在毫秒级。**任何"用模型换准确率"的方案，都应该先和"把这些算力花在 RS 多假设上"比较。**

## 2.6 多帧：F=2 是陷阱，F=3 才有效

【本地实验】独立错误假设，单帧模块错误率 8.7%：

| 帧数 | 残余错误率 | 擦除率 | 预算占用 e+2t | 结论 |
|---|---|---|---|---|
| F=1 | 8.70% | 0 | 44.4 / 32 | 超预算 |
| F=2（一致才接受，否则擦除） | 0.76% | **15.89%** | 44.4 / 32 | **仍超预算** |
| F=3（多数表决） | 2.14% | 0 | 10.9 / 32 | **可解** |
| F=5 | 0.58% | 0 | 2.9 / 32 | 可解 |

**两帧不一致率 2p(1−p)=15.9% 会吃掉全部擦除预算**，这是很多"多帧融合"实现踩的坑。**三帧多数表决**才是第一个真正有效的点。

⚠️ 独立性假设很强。真实手持连拍的模糊/透视高度相关。**只有在亚像素相位、噪声、局部光照有差异时独立性才近似成立**——这正是手持多帧超分的物理基础【论文：Handheld Multi-Frame Super-Resolution, 2019, https://arxiv.org/abs/1905.03277】。你们已有的 canonical 叠加是**像素级**的，只降随机噪声；**模块级后验合并是分类之后的融合，能修复"单帧硬判错"**，两者不等价，后者强得多。【解析】

2. 本实验只能支持**相对排序**与**成本量级**结论，不能预测端到端收益。
3. 训练集是四个桶的混合，拟合法与你们"用 C 实际残差训练"的做法一致，但域偏移的具体形态不同。
4. `brutal` 桶（模块 5 px、σ≈1.6 px）所有方法都掉到 12–19%，接近 8 分类随机（12.5%）——**这是信息论下限，不是模型问题**。

**能站得住的三条结论**：
- **① 在同一个（有偏移的）观测域上训练线性判别器，比解析模板 NCC 高 26–36 个点，且便宜 40–245 倍。** 这与你们"C 残差训练的 width8 CNN 达 96.1%"是同一现象的更廉价版本。
- **② Hann 加窗（M1w）反而变差**：加窗抑制了邻域串扰，但也削掉了笔画端点的有效证据。**不要做加窗**——这是一个新的负结果。
- **③ 强退化下所有方法的置信度都退化到接近随机**（cap@10%≈0.10）。⇒ 再次印证 2.4：**可靠度必须来自分类器之外**。

## P1｜RS 擦除 + GMD/Chase 多档扫描 + CRC32 列表选择 ★★★★★

**核心思想**  
把 RS 从 errors-only 升级为 errors-and-erasures，按模块可靠度排序，扫若干擦除档位 `e ∈ {0,4,8,…,n−k}`，每档解一次，用**已有的 CRC32** 从候选列表里挑正确码字。这就是 Forney 的 GMD（1966）+ Chase 型翻转 + 极化码里的 CRC 辅助列表选择，三者的组合。

**与 LCC 的契合点**
- LCC **已经有 CRC32**：等于免费拥有一个 32 bit 的候选验证器，误接受概率 ≈2⁻³²。这让"多假设解码"从零风险变成几乎零风险。
- LCC 是**分块交织**的：一个模块的错误会落到少数几个块上，擦除标记可以精确投放。
- 若采用 P2 的"模块=符号（限字母表 0..7）"，**解出 >7 的符号本身就是确定性错误检测**，可以自动生成擦除位置。

**预期收益**
- 【本地实验】上界：模块 91.3%、s=1 时，块可解率 9.93% → **98.56%**（oracle 擦除）。
- 【本地实验】现实：置信度 AUC≈0.92 时 → **29.9%**；AUC≈0.98 时 → **73.6%**。
- 【推测】你们真实照片 4/13 中，"RS 超预算但差得不多"的帧有望救回 1–3 张；blur_shape 有望 +5～15 pt（**前提是 P3 提供足够好的可靠度**）。

**训练与推理成本**
- 训练：**零**。
- 推理：【本地实验】单次解码 ≈13,008 GF(256) 乘加；32 档 ≈0.42 M GF-op/块。8 块全扫 ≈3.4 M GF-op ≈ 毫秒级。**代码体积增加 <3 KB**（复用现有 BM/Chien/Forney，只需加擦除多项式）。

**C/WASM 实现难点**
1. 擦除定位多项式 Λ_e(x) 与 Forney 修正：需要修改 syndrome → BM 的初始化（用擦除定位多项式做初值），这是标准做法但容易写错符号约定。
2. 交织索引映射：模块可靠度 → 符号可靠度 → 块内位置，三层索引必须有单元测试。
3. **早停**：一旦某档 CRC 通过立即返回；档位按"预期收益"排序而不是从小到大。
4. GF(256) 乘法表已在用，无需新增。

**最小验证实验（1–2 天）**  
在**不改任何前端**的情况下，用**真值 payload 反推**得到"哪些模块错了"，做 **oracle 擦除**解码，统计端到端上限。这个数字直接告诉你 P1+P3 的天花板。

**Kill criteria**
- 若 oracle 擦除下端到端提升 **< 3 pt**，说明失败帧不是"差几个符号"而是"整片崩"，**P1 降级**，转 P2/P10。
- 若真实可靠度下（P3 完成后）提升 < 2 pt 且 AUC < 0.8，**先修 P3 再回来**，不要加档位。

**如果只能做一个实验**：**做 oracle 擦除上界实验。** 它一天内就能告诉你"整个 RS 软判决方向值不值得投"，而且不需要训练任何模型。

**来源**：Forney GMD 1966 https://doi.org/10.1109/TIT.1966.1053873 ；Chase-type RS https://arxiv.org/abs/1309.1555 ；CRC 辅助列表 https://arxiv.org/abs/1206.0050 ；RS 擦除界 https://en.wikipedia.org/wiki/Reed%E2%80%93Solomon_error_correction 【论文+解析+本地实验】

## P2｜打包与块长审计 / 重设计（格式层，零推理成本）★★★★★

**核心思想**  
先**测量** s（每符号涉及的不同模块数）与块长，再决定是否改。三个候选改动，按代价从低到高：A′ 组对齐（免费）→ 短块 RS（2× 容量代价）→ 模块=符号（3× 容量代价）。

**与 LCC 的契合点**  
形状层是 **3 bit/模块**，与 GF(256) 的 8 bit 符号**天然不整除**。这是 LCC 特有的结构性问题，通用 QR 文献里没有。基础层里 8 bit/模块的层（L4e/L4f）天然 s=1，**只有形状层和低位宽层受害**。

**预期收益**（【本地实验】`packing_tradeoff.py`，见 2.1 表）
- A→A′：可容忍模块错误 1.71%→1.88%，**完全免费**。
- A→C：1.71%→**6.27%**（3.7×），擦除容忍 3.42%→**12.55%**，代价 2.7× 比特。
- A→B（短块 RS(64,32)）：1.71%→**6.82%**，代价 1.75× 比特。
- **B 是性价比最高的单点改动**：容量只降 43%，容忍度翻 4 倍。

**训练与推理成本**：训练零；推理零（块短了 RS 反而更快）。**代价是容量**，需要产品侧决策。

**C/WASM 实现难点**
- 编码器/解码器必须同步改，且要**版本门控**（格式带里加一位/复用保留位）。
- 建议做成**按层可配置**：形状层用短块/模块对齐，高位宽基础层保持现状。这样容量损失只落在最脆弱的层上。
- 旧码兼容：保留旧路径，用版本号分派。

**最小验证实验（0.5 天审计 + 1 天离线重放）**  
用现有 240 帧的**模块级判决结果**离线重打包 + 重跑 RS（纯 Python/JS 即可，不用改 C），对比四种打包的端到端。**这是纯离线实验，零风险。**

**Kill criteria**
- 若审计发现现状已是 s=1 且块长 ≤64，本方案的收益空间已被吃掉，**只做 A′**。
- 若产品侧不接受任何容量下降，**只做 A′ + P1**。

**如果只能做一个实验**：**统计 s 的直方图和每块 (n,k)。** 半天的事，但它决定后面所有方案的收益上限。

**来源**：【本地实验】`packing_tradeoff.py`；RS 界同上；符号级软信息映射 https://www.ideals.illinois.edu/items/138091/bitstreams/448992/data.pdf 【解析+论文】

## P3｜多源可靠度图 + 概率校准 ★★★★★

**核心思想**  
不要用分类器 margin 当唯一置信度。构造每模块可靠度  
`r = w1·cal(margin) + w2·几何重投影残差 + w3·局部模糊/对比度 + w4·颜色拟合残差 + w5·邻域/跨层一致性`，  
并用**等温回归或 Platt 校准**把它映射成真实错误概率，再转成符号可靠度。

**与 LCC 的契合点**
- LCC 的失败模式**高度结构化**：透视估计误差 → 图像边缘模块系统性偏移；光照 → 局部对比度塌陷；摩尔纹 → 特定频段的周期性干扰。**这些都能在读模块时廉价测出来**，而且**与分类器 margin 正交**。
- timing 行/列 + alignment 提供了**免费的几何自检**：网格重投影到 timing 上的一致性就是逐区域的几何可靠度。

**预期收益**
- 【本地实验】这是 P1 生效的**必要条件**：AUC 从 0.76→0.92 使块可解率从 10.8%→29.9%（模块 91.3% 时）。
- 【推测】几何+模糊两路信号在 blur_shape 上应能把 AUC 推到 0.9 以上，因为强退化帧的错误在空间上是成片的（我的代理实验里 margin 失效，但模糊程度是可直接测量的）。

**训练与推理成本**
- 训练：一个 5–8 维的逻辑回归/等温回归，**几百个参数**，用已导出的 C 残差 + 真值标签即可。
- 推理：每模块几十次运算 + 一次逐区域的高斯模糊估计（可在网格图上做，O(N²)）。**代码 <2 KB**。

**C/WASM 实现难点**
- 几何重投影残差：需要在采样时顺便记录亚像素相位与局部单应性残差，**几乎免费**（已有 warp 代码）。
- 局部模糊估计：用模块内 16×16 残差的高频能量占比即可，`E_hf/E_total`，一次投影就能算。
- 校准表要**离线固化成查找表**，不要在 WASM 里跑等温回归。

**最小验证实验（2 天）**  
在导出的 367,755 个模块上，加 4 个辅助特征，训练逻辑回归预测"该模块是否错"，报告 **AUC / ECE / risk–coverage**，并把它喂给 P1 的 GMD。**对比"只用 margin"的 AUC。**

**Kill criteria**
- 若融合后 AUC 仍 < 0.80，**P1 的现实收益会很小**（见 2.4 表），此时应先做 P10（几何精修）把系统性错误消掉，而不是继续堆可靠度特征。

**如果只能做一个实验**：**测"仅 margin"与"margin+几何+模糊"的错误检测 AUC 差值。** 这一个数字决定 P1 的实际价值。

**来源**：【本地实验】`rs_budget_model.py` 段 C；校准与 TTA 的样本筛选思想 https://arxiv.org/abs/2204.02610 【解析+论文】

## P4｜投影特征（Radon-lite）+ 线性判别分类器 ★★★★★

**核心思想**  
16×16 残差 → **行投影(16) + 列投影(16) + 主对角投影(16) + 反对角投影(16) + 4 个环带能量 = 68 维**，再过一个 68×8 的线性分类器（岭回归/逻辑回归闭式解）。

**为什么这对 LCC 特别合适（inductive bias）**
- 8 种形状**本质上就是"哪个方向上有线"**：`-`→行投影单峰；`|`→列投影单峰；`+`→两者；`/`→反对角；`\`→主对角；`X`→两对角；`square`→行/列双峰在边缘；`blank`→全平。
- **投影 = 沿一个方向求和**，会**平均掉噪声（SNR ↑ √16）**，而模糊只是把 1D profile 抹平 —— **投影对模糊天然鲁棒**。这正是强模糊下它反而比模板 NCC 强的原因。
- 投影是**线性算子**，与模糊、2×2 平均、光照归一化**可交换**，所以"独立渲染 vs C 实际残差"的域偏移在投影域里**小得多**。

**与 LCC 的契合点**：线宽/inset 变化只改变 profile 的宽度，不改变峰的位置；对比度反向只改符号，取绝对值或让线性层自己学。

**预期收益**
- 【本地实验】medium 桶 **76.0% vs 模板 NCC 49.3%（+26.7 pt）**；hard 桶 **43.9% vs 21.2%（+22.7 pt）**。
- 【推测】在你们真正的 C 残差上，应能达到或超过 width8 CNN 的 96.1%，因为 CNN 学到的很可能就是这类方向性统计。

**训练与推理成本**
- 【本地实验】**1,568 MAC/模块**，是 width8 CNN（385,000）的 **1/245**。
- 参数：68×8+8 = **552 个参数**，int8 后 **<600 字节**。
- 【解析】按你们 0.195 ms/模块 ÷ 245 ≈ **0.8 µs/模块**；v10 全网格 ≈ **2.6 ms**。**可以默认开启。**

**C/WASM 实现难点**
- 对角投影需要按 `y−x` / `y+x` 累加，**不是连续访存**。解法：预计算索引表，或按行滚动累加到两个长度 31 的缓冲区（每行一次偏移加法），**完全向量化友好**。
- 更省的做法：**对角投影可以只用中心 ±5 条**（笔画集中在中心区），把 31 条降到 11 条再重采样。
- int8 量化：投影值动态范围大（求和 16 个 int8），用 int16 存投影、int8 存权重，`extmul + extadd_pairwise` 累加到 i32。

**最小验证实验（2 天）**  
在已有 367,755 个 C 残差上训练，**与 width8 CNN 在同一测试集上对比模块准确率 + 每模块耗时**。

**Kill criteria**
- 若模块准确率比 width8 CNN **低 1.5 pt 以上**，先试 P5（低秩度量）；若两者都不如 CNN，说明 C 残差里有非线性结构，**保留 CNN 但用 P11 压缩**。
- 若准确率相当但端到端无提升 → 说明瓶颈确实在 RS（回到 P1/P2），**这本身就是有价值的结论**。

**如果只能做一个实验**：**用现有 C 残差训一个 68→8 的岭回归，和 width8 CNN 比准确率与耗时。** 一天，几乎零风险，收益可能是"模型层从可选变默认"。

**来源**：【本地实验】`proxy_shape_experiment.py` M3；Radon/Hough 经典（Duda & Hart, CACM 1972）；判别式模板思想 https://doi.org/10.1109/TPAMI.2009.167 【本地实验+论文】

## P5｜低秩白化 + 可学习类模板（判别式度量学习）★★★★☆

**核心思想**  
`256 维残差 → PCA 到 32 维并白化 → 类内白化（LDA 度量）→ 与 8 个学习到的类原型算距离`。  
等价于"把 NCC 的欧氏度量换成学出来的 Mahalanobis 度量，并把解析模板换成学出来的原型"。**模板不再是画出来的，是学出来的。**

**与 LCC 的契合点**
- 8 个原型可以**用解析模板初始化**，再用 C 残差微调 —— 这是原型网络的标准做法，**小样本友好**，正好对应"真实难例很少"。
- 白化矩阵会自动学到"哪些像素方向是噪声/邻域串扰"，把它们压掉。**这正是你们 SR 方案失败的根因（邻域串扰 + 整数化）的判别式解法**。

**预期收益**
- 【本地实验】easy **89.3%**、medium **85.7%**，是所有方法里最好的；且 **cap@10%=0.511/0.382**，**置信度质量也最好**（对 P1/P3 极其重要）。
- 【推测】在 C 残差上应与 width16 CNN（97.0%）相当。

**训练与推理成本**
- 【本地实验】**9,472 MAC/模块**（256×32 投影 + 32×32 白化 + 8×32 距离），CNN 的 **1/41**。
- 参数：256×32 + 32×32 + 8×32 = **9,472 个参数**，int8 ≈ **9.5 KB**。**这是唯一需要注意体积的方案**（默认 140 KB 的 7%）。
- 可降到 rank 16：投影 4,096 + 256 + 128 = **4,480 MAC / 4.5 KB**，外推 **2.27 µs/模块 → 7.4 ms/帧**（rank32 为 4.80 µs → 15.6 ms）。

**C/WASM 实现难点**
- 256×32 的 int8 GEMV 是主要成本，**必须 SIMD**：`extmul_low/high_i8x16_s → extadd_pairwise → i32 累加`。
- 白化可以**离线合并进投影矩阵**（P·W 预乘），运行时只剩一个 256×32 矩阵 + 8 个原型。**这一步必须做，能省一半算力。**
- 距离用平方欧氏即可，不要开方。

**最小验证实验（2 天）**  
同 P4，但用 rank ∈ {8,16,32} 三档，画 **准确率 vs MAC vs 体积** 的 Pareto。

**Kill criteria**
- 若 rank16 相比 rank32 掉 >1 pt，且 rank32 体积不可接受 → 退回 P4。
- 若置信度 AUC 不显著优于 P4，则 P5 的唯一优势（校准好）消失，选更便宜的 P4。

**如果只能做一个实验**：**rank16 版本**（4.5 KB / 4.5 k MAC）与 width8 CNN 对比。这是体积/算力/准确率的最佳折中点。

**来源**：【本地实验】M4；Prototypical Networks https://arxiv.org/abs/1703.05175 ；DPM 判别式模板 https://doi.org/10.1109/TPAMI.2009.167 【本地实验+论文】

## P6｜笔画原子子空间 GLRT（结构化 analysis-by-synthesis）★★★☆☆

**核心思想**  
利用 LCC 的一个漂亮结构：**8 个形状 = 5 个笔画原子 {/, \, −, |, □} 的子集**（`X = / + \`，`+ = − + |`，`blank = ∅`）。  
把每个原子按若干模糊档位渲染成模板，去掉 offset/线性光照 nuisance，QR 正交化得到 5 维基 Q；对 8 个假设各预计算一个 5×5 矩阵 M_H，使得  
`‖P_H r‖² = uᵀ M_H u`，其中 `u = Qᵀ r`。  
运行时：**每档 5 次 256 长点积 + 8 次 5×5 二次型**，取 penalized 残差最小的假设。

**与 LCC 的契合点**：这是把"已知模板 + 已知形变自由度（模糊/线宽/相位/增益/光照）"直接写成生成模型，**是 SR 的正确替代品**——不重建像素，而是在观测域做参数化匹配。

**预期收益**
- 【本地实验】easy 80.2%、medium 54.6%：**比解析模板好，但明显不如 P4/P5**。
- 原因分析【推测】：我的原子库只建模了模糊，**没有建模邻域串扰和亚像素相位**，而这两项恰恰是 C 残差的主要偏移源。
- ⇒ **如果把 nuisance bank 扩展到 (模糊 × 相位 × 线宽)，理论上会显著变好，但 bank 大小乘性增长**。

**训练与推理成本**
- 【本地实验】6 档模糊 = **13,488 MAC/模块**，外推 **6.83 µs/模块 → 22.2 ms/帧**。若加 4 个相位 × 3 个线宽 → 72 档 → **162 k MAC → 267 ms/帧**，逼近 CNN。**这是本方案的致命成本曲线。**
- 训练：几乎为零（纯解析 + 一个惩罚系数 λ）。**这是它最大的优点：不需要标注数据。**

**C/WASM 实现难点**
- 全部是小矩阵乘，极易 SIMD；bank 是常量表，`6 档 × (256×5 + 8×25) = 8.7 KB`（int8 后）。
- 相位/线宽扩展会让表爆到 100 KB 量级，**与 140 KB 默认体积目标冲突**。

**最小验证实验（1 天）**  
在 C 残差上直接跑（**零训练**），看它能否超过模板 NCC。这是一个"免训练基线"，值得作为 P4/P5 的对照。

**Kill criteria**
- 若在 C 残差上不如 P4 的线性分类器（很可能），**只保留它作为"无训练数据时的冷启动方案"**，不作为主路径。
- 若扩展 nuisance bank 后仍不如 P5，**放弃**。

**如果只能做一个实验**：**零训练直接跑 C 残差**，一天内得到"结构化先验能走多远"的答案。

**来源**：Matched Subspace Detectors https://ieeexplore.ieee.org/document/301849/ ；SRC https://doi.org/10.1109/TPAMI.2008.79 ；可变形模板 https://doi.org/10.1007/BF00127169 ；【本地实验】M2 【论文+本地实验】

## P7｜颜色 × 形状联合似然 + 跨层/邻域一致性 ★★★★☆

**核心思想**  
不再"先形状后颜色"，而是对每模块枚举 **联合假设 (色板索引 c, 形状 s)**，计算联合似然 `L(c,s) = L_color(c) · L_shape(s | c, 对比度方向, 线宽)`，再对两个层分别边缘化得到各自的软输出。

**为什么值得（三条具体机制）**
1. **形状判别依赖对比度方向**：前景比背景亮还是暗，决定了残差的符号。先定颜色能给形状一个**强先验**，而不是让形状分类器自己去猜符号（我的合成器里 10% 对比度反向，模板 NCC 在这上面损失明显）。
2. **颜色分类依赖"背景估计"**：而背景估计的误差正是形状残留造成的。**两者互为噪声**，联合建模能同时消掉。
3. **跨层一致性**：同一模块的基础层与形状层共享同一块物理区域，**几何/模糊/光照的 nuisance 参数是共享的**。联合估计 nuisance 比各层独立估计更准。

**与 LCC 的契合点**：LCC 的分层结构本来就是"同一模块承载多层信息"，这是它相对普通 QR 的**独有优势**，目前完全没有利用。

**预期收益**【推测】
- 颜色层符号错误率下降 → 直接减少 RS 预算占用；
- 形状层在对比度反向/低对比度模块上提升；
- **但收益幅度我没有直接证据**，这是本报告里不确定性最高的方案之一。

**训练与推理成本**
- 若色板 K=8、形状 8 → 64 个联合假设。朴素实现 64×256 = 16 k MAC/模块。
- **可分解**：`L(c,s) = L_color(c) + L_shape(s|c)`，形状对 c 的依赖只通过**符号与增益**两个标量 ⇒ 实际只需 `K 次颜色打分 + 2 次形状打分（正/负对比度）`，**≈ 2× 单层成本**。
- 训练：需要**联合标注**（颜色真值 + 形状真值），你们的导出 API 应该已经能同时给出。

**C/WASM 实现难点**
- 需要重构解码顺序：从"形状→颜色校准"变成"粗颜色→联合→精校准"，**改动面比 P1–P5 大**。
- 颜色校准是全局的（色板），形状是局部的，两者的迭代要小心不要引入振荡；建议**只做一轮**。

**最小验证实验（3 天）**  
先做最便宜的版本：**用当前颜色判决结果给形状分类器加 2 维条件特征（对比度符号、局部对比度幅度）**，看模块准确率是否提升。这是联合建模的 1% 成本版本。

**Kill criteria**
- 若加 2 维条件特征提升 < 0.5 pt，**联合建模的完整版本大概率也不值得**，直接放弃。

**如果只能做一个实验**：**给 P4 的分类器加"对比度符号 + 幅度"两维特征。** 半天，直接检验联合建模的核心假设。

**来源**：【推测】为主；可变形模板中" nuisance 参数共享"的思想 https://doi.org/10.1007/BF00127169 ；屏拍颜色退化建模 https://dl.acm.org/doi/10.1145/3503161.3548049

## P8｜多帧模块级后验合并（不是像素叠加）★★★★☆

**核心思想**  
每帧独立算出**每模块的 8 类后验**，跨帧对齐到 canonical 网格后**相乘（对数相加）**，再硬判/软判。与你们已有的像素级 canonical 叠加**完全不同**：融合发生在分类之后，能纠正单帧的硬判错误。

**与 LCC 的契合点**：扫描路径本来就是连续帧；canonical 对齐已实现，**复用现成基础设施**。

**预期收益**
- 【本地实验】独立假设下，单帧 8.7% 错误：**F=3 多数表决 → 2.14%，预算占用 10.9/32，可解**；F=5 → 0.58%。
- **F=2 是陷阱**：不一致率 15.9% 会吃满擦除预算，仍超支。
- 【推测】真实手持连拍相关性高，实际增益会打折；但**亚像素相位差异**带来的是真实信息增益【论文：https://arxiv.org/abs/1905.03277】。

**训练与推理成本**
- 训练零。推理：每帧正常成本 + 每模块 8 次加法。**几乎免费**。
- 内存：canonical 网格 × 8 类后验，v10 = 3249×8×2B ≈ **52 KB**。可接受。

**C/WASM 实现难点**
- 跨帧对齐精度决定一切：**亚模块级对齐误差会让合并变成模糊**。建议用 finder+alignment 的单应性把每帧网格映到同一 canonical，再做**相位一致性检查**，不一致的帧直接丢弃。
- 需要"何时停止收帧"的策略：CRC 通过即停；否则最多 5 帧。
- **独立性检验**：如果两帧的模块判决完全一致但都错（相关性高），合并无益。可用"帧间不一致率"作为多样性指标，低于阈值就提示用户移动手机。

**最小验证实验（2 天）**  
在合成器里生成同一码面的 3–5 帧（不同相位/噪声/模糊），离线合并后验，测端到端。**再做真实连拍验证相关性假设。**

**Kill criteria**
- 若真实连拍的 F=3 相比单帧提升 < 5 pt，说明帧间相关性太强，**改为"引导用户改变视角"的交互策略**而不是算法合并。

**如果只能做一个实验**：**测真实连拍的帧间模块判决不一致率。** 如果 < 3%，独立性假设破产，整个方案要重新设计。

**来源**：【本地实验】`rs_budget_model.py` 段 D；Handheld MFSR https://arxiv.org/abs/1905.03277 【解析+论文】

## P9｜二值化变体预测/剪枝 + ROI + 失败早停 ★★★★☆

**核心思想**  
三件事：
1. **12 种二值化不再固定顺序全试**：用整帧/ROI 的廉价统计（灰度直方图双峰性、局部对比度、饱和度分布、梯度能量）预测最可能成功的 2–3 种，其余按需；
2. **ROI 优先**：先在缩小图上定位候选区域，只在 ROI 上建 mask 与找 finder；
3. **失败早停**：用 P3 的可靠度图算"预算占用预测 Û"，若 Û ≫ 1（例如预测错误率 >15%），**立即放弃该分支，不跑模型、不跑 RS 多档**。

**与 LCC 的契合点**
- 12 种变体 × 整图 mask 是当前 53 ms 的主要来源之一；
- LCC 的 finder 是自定义 1:2:1:2:1 同心方环，**在 ROI 上做环形径向剖面验证极便宜**；
- 早停直接对应 2.3 的发现：**p>15% 的帧（约 5–10%）任何手段都救不了**。

**预期收益**
- 【推测】平均耗时 53 ms → **20–30 ms**（干净帧不退化，难帧省掉无用分支）；
- **p95 耗时显著下降**，这是你们明确的目标之一；
- 识别率中性偏正（省下的算力可以给 P1 的多档 RS）。

**训练与推理成本**
- 训练：一个 12 类的排序器（GBDT 或逻辑回归），特征 ~20 维，**几千个参数**；或者干脆用**手工规则 + 离线调参**，零模型。
- 推理：整帧一次统计 O(像素数)，**远小于 12 次 mask**。

**C/WASM 实现难点**
- 需要保证**剪枝不会漏掉本来能解的帧**：保留"前 3 种失败后回退全扫"的路径，但这会让最坏情况变慢。建议**按 ROI 质量决定回退深度**。
- 早停阈值必须**保守**：用离线数据把"误杀率"（本来能解却被早停）压到 <0.5%。

**最小验证实验（2 天）**  
离线记录 240 帧上"哪种二值化最终成功"，训练排序器，测 **top-1/top-3 命中率** 与 **平均尝试次数**。

**Kill criteria**
- 若 top-3 命中率 < 85%，剪枝风险太大，**只做 ROI 与早停，不做变体剪枝**。

**如果只能做一个实验**：**统计 240 帧上成功变体的分布。** 如果发现 80% 的成功集中在 3 种变体上，直接把固定顺序改成静态优先级即可，连模型都不用。

**来源**：EgoQR（ROI + 高效解码）https://arxiv.org/abs/2410.05497 ；ADNet（按模糊程度自适应选网）https://arxiv.org/abs/2510.12098 ；LightGlue（自适应早退）https://arxiv.org/abs/2306.13643 【论文+推测】

## P10｜几何 / 模糊的 grey-box 精修（可验证优化，而非端到端回归）★★★☆☆

**核心思想**  
不做端到端单应性回归。做 **"经典初值 + 参数化精修 + 结构约束验证"**：
1. 用 finder/alignment 得到 H₀；
2. 在 **timing 行/列 + alignment + 模块边界** 上定义重投影能量，用 **inverse-compositional Lucas-Kanade** 迭代精修 H（6–8 参数），每步只需几个梯度点积；
3. 对运动模糊：用**小网络或经典方法估计模糊核参数（长度/方向）**，然后做**容差引导的候选搜索 + 正则化线性反演**，而不是让网络直接吐像素。

**与 LCC 的契合点**
- LCC 有 **timing 行/列**：这是一条**已知的高频交替图案**，是天然的、密集的对齐目标函数，比普通 QR 只有 3 个 finder 强得多。
- 三个 finder + 一个 alignment 提供 **4 点 = 8 约束**，单应性 8 自由度 ⇒ **恰好可解且可验证**；再加 timing 就是**超定**，可以做 RANSAC 式一致性检验，**直接输出几何可靠度**（喂 P3）。

**预期收益**
- 【论文】最接近的证据：2026-10 的 QR 运动模糊工作，**grey-box（小网络出参数 + 容差引导搜索 + 交替拟合 + 正则化线性反演）在 955 张真实手机照片上精确 payload 恢复 93.1%，vs 最强微调去模糊网络 83.6%**。这是"参数化模型 > 像素级网络"的直接实证。
- 【推测】LCC 的 eval 240 帧（含透视）16.7% 里，有相当部分是几何微偏导致的**成片模块错误**；精修 H 可能比形状分类器更有效。

**训练与推理成本**
- 几何精修：**零训练**，纯优化。每次迭代 O(采样点数)，10 次迭代 ≈ 几十万次运算，**亚毫秒**。
- 模糊参数估计：经典方法（谱零点/倒谱）零训练；若用小网络，输入 32×32 频谱，输出 2–4 个参数，**<5 k 参数**。
- 线性反演：若做 Wiener/Tikhonov 正则化反卷积，在 16×16 模块上是小矩阵，**但会放大噪声**，建议只在"估计出的模糊核可信"时启用。

**C/WASM 实现难点**
- IC-LK 需要 Hessian 预计算与稳健的收敛判据；**必须限制迭代次数与步长**，否则失败路径会退化到几百 ms。
- 模糊核估计在摩尔纹存在时极不稳；**必须先做摩尔纹检测并跳过**。
- 反演要加正则化，且**必须用下游 RS 是否成功来验证**，不能用像素指标。

**最小验证实验（3 天）**  
只做几何精修：在 eval 240 帧上，用 timing 一致性作为目标函数精修 H，测 **finder 后置的网格对齐误差** 与 **端到端**。

**Kill criteria**
- 若几何精修后 eval 端到端提升 < 3 pt，说明几何不是 eval 的主要瓶颈，**停止投入模糊反演**（那部分成本高得多）。

**如果只能做一个实验**：**测量 eval 失败帧的"网格对齐误差"分布**（用真值 payload 反推理想网格）。如果失败帧的对齐误差与成功帧无显著差异，**整个 P10 可以直接砍掉**。

**来源**：https://arxiv.org/abs/2610.34788 （2026，93.1% vs 83.6%）；Deep Lucas-Kanade Homography https://arxiv.org/abs/2104.11693 ；ADNet https://arxiv.org/abs/2510.12098 【论文+推测】

## P11｜极致压缩与 SIMD 内核（int8 / 二值 / 查表 / 树蒸馏）★★★☆☆

**核心思想**  
在 P4/P5 已经把算力降 40–245× 之后，再考虑：
- **int8 量化 + 基线 SIMD 内核**（必做）；
- **二值化模板匹配**：把 16×16 残差二值成 256 bit，与 8 个学习到的二值模板做 XOR+popcount，**`i8x16.popcnt` 全平台可用**，8 个模板 = 16 个 v128 操作，**几乎零成本**；
- **树蒸馏**：把 P4/P5 的线性分类器（或 CNN）蒸馏成 **深度 4–6 的 GBDT**，在 68 维投影特征上，推理只要几十次比较，**无需 SIMD、代码 <2 KB**；
- **查表（LUT）**：把投影特征分组量化后查表，参考 PolyLUT/NeuraLUT 的思路。

**与 LCC 的契合点**：8 类、低维、强结构 —— 这是树模型和 LUT 最擅长的场景。

**预期收益**【推测】
- 二值模板：可能达到 P4 的 90–95% 水平，但成本降到 1/10；
- 树蒸馏：准确率损失通常 <1 pt（在低维表格特征上），**推理成本降到 ~50 次比较**；
- **但这些都是在 P4 已经很便宜之后的边际优化**，优先级低于 P1–P5。

**训练与推理成本**
- int8 量化感知训练：标准流程，成本低。
- **WASM int8 点积的关键事实**【工程】：`i32x4.dot_i8x16_i7x16_add_s` 属于 **Relaxed SIMD，Safari/iOS/Firefox 不支持**。必须用基线路线：  
  `i16x8.extmul_low_i8x16_s / extmul_high → i32x4.extadd_pairwise_i16x8_s → i32x4.add` 累加。  
  注意 int8×int8 的积在 i16 里**只能安全累加 2 项**（127×127×2 = 32258 < 32767），**必须立刻 widen 到 i32**，这是最常见的溢出 bug。
- 二值路线用 `i8x16.popcnt`（基线 SIMD，96.78% 支持）。

**C/WASM 实现难点**
- 量化尺度必须**逐层固定为 2 的幂**，避免运行时除法；
- 树模型在 WASM 里是分支密集代码，**分支预测失败率高**，实测可能不比 SIMD 线性层快 —— **必须实测，不要假设**；
- 保持默认构建小：所有模型代码继续放 `LCC_ENABLE_MODELS=1` 后面，但 P4 只有 ~600 B 权重，**可以考虑破例默认开启**。

**最小验证实验（2 天）**  
在 P4/P5 训好的模型上做 int8 量化，测准确率损失与 WASM 实测耗时；再训一个 GBDT 对照。

**Kill criteria**
- 若 int8 损失 > 1 pt，改用 int16 权重（体积翻倍但仍很小）；
- 若 GBDT 在 WASM 里不比 SIMD 线性层快，**放弃树路线**（这在 x86 上常见，WASM 上更甚）。

**如果只能做一个实验**：**把 P4 的 68×8 线性层用基线 SIMD int8 实现，实测 µs/模块。** 这决定"模型层能否默认开启"。

**来源**：WebAssembly SIMD 规范 https://github.com/WebAssembly/simd/blob/main/proposals/simd/SIMD.md ；Relaxed SIMD Overview https://github.com/WebAssembly/relaxed-simd/blob/main/proposals/relaxed-simd/Overview.md ；caniuse https://caniuse.com/wasm-relaxed-simd ；CMSIS-NN https://arxiv.org/abs/1801.06601 ；XNOR-Net https://arxiv.org/abs/1603.05279 ；TreeLUT https://arxiv.org/abs/2501.01511 【工程+论文】

## P12｜数据引擎：失败帧强制对齐 + 屏拍噪声层 + 轻量 TTA ★★★★☆

**核心思想**  
三个子项：
1. **失败帧强制对齐**：合成数据的 payload 已知 ⇒ 可以**反推真值模块网格**，即使解码器完全失败也能导出残差与标签。这补上你们训练集最大的缺口（现在只有"能走到数据模块"的 180/240 帧）。
2. **屏拍噪声层**：按 PIMoG 的思路把摩尔纹、屏幕栅格、透视、光照写成**参数化可微噪声层**，随机化**正确的轴**。
3. **轻量 TTA**：每帧只更新**增益/偏置/白平衡/色板仿射**这几个标量，用高置信模块做自监督，**不动网络权重**。

**与 LCC 的契合点**
- 合成器可控 + payload 已知 ⇒ **强制对齐是"免费标注"**，这是你们相对通用 CV 任务的巨大优势，目前没用满。
- LCC 的颜色层本来就有"分通道白平衡/色板校准"⇒ **TTA 的更新对象已经存在**，不需要引入 BN 层。

**预期收益**
- 【推测】失败帧残差补进训练集后，难尾上的模块准确率提升；这是唯一能覆盖"当前训练集完全没见过的分布"的手段。
- 【论文】PIMoG 自报在屏拍水印任务上提取准确率至少 +5%；TinyTTA 自报边缘 TTA 准确率最高 +57.6%、内存降至 1/6。**但这些都不是 LCC，收益需实测。**

**关于"哪些增强真正对应手机失败模式"（回答 F2）**  
按重要性排序【推测，需用真实照片验证】：
1. **亚像素相位 + 局部单应性微偏**（我的代理实验里这是模板 NCC 掉分的主因）
2. **邻域串扰**（模块边界外的笔画进入采样窗口）—— **独立渲染模块的训练集完全没有这一项，这正是你们 SR 失败的根因**
3. **各向异性运动模糊**（不是各向同性高斯）
4. **JPEG 块效应 + 色度下采样**（4:2:0 会直接损伤彩色码的颜色层，**建议重点检查你们合成器是否模拟了色度下采样**）
5. **屏幕摩尔纹**（与采样栅格耦合的乘性周期干扰）
6. **局部高光/阴影导致的对比度塌陷**
7. 传感器噪声（**最不重要**，你们可能过度随机化了这一项）

**避免合成过拟合**：把**真实照片的退化参数分布**测出来（模糊核、噪声水平、色偏、摩尔纹频率），用它们**校准合成器的参数分布**，而不是凭感觉设范围。13 张真实照片虽少，但足以估计这些低维统计量。

**训练与推理成本**
- 强制对齐导出：离线，零推理成本。
- 噪声层：离线训练成本。
- TTA：每帧几十次标量更新，**<0.1 ms**。

**C/WASM 实现难点**
- 强制对齐需要一个"给定 payload + 版本 → 真值模块矩阵"的 C API（编码器已有，复用即可）。
- TTA **必须防止发散**：SAR 论文明确指出小 batch/混合偏移下 TTA 会变差【论文 https://arxiv.org/abs/2302.12400】。建议：只更新 2–4 个标量、限幅、CRC 失败则回滚。

**最小验证实验（3 天）**  
导出失败帧残差，加入训练集，重训 P4，测**难尾帧**（p>5% 的那一段）的模块准确率与端到端。

**Kill criteria**
- 若加入失败帧后**易帧准确率下降 >0.5 pt** 且难帧提升 <2 pt，说明失败帧的残差本身信息量不足（对应 2.7 的 brutal 桶），**不要为了覆盖它们牺牲主分布**。
- TTA 若在 13 张真实照片上出现任何一张变差，**默认关闭**。

**如果只能做一个实验**：**导出 60 个失败帧的强制对齐残差，看它们的模块级"可分性"（用 P4 分类器的 oracle 训练上界）。** 如果连训练集上都分不开，说明信息已经丢失，数据引擎也救不了。

**来源**：PIMoG https://dl.acm.org/doi/10.1145/3503161.3548049 ；StegaStamp https://arxiv.org/abs/1904.05343 ；TENT https://arxiv.org/abs/2006.10726 ；SAR https://arxiv.org/abs/2302.12400 ；TinyTTA https://proceedings.neurips.cc/paper_files/paper/2024/hash/4c454d34f3a4c8d6b4ca85a918e5d7ba-Abstract-Conference.html ；Domain Randomization https://arxiv.org/abs/1703.06907 【论文+推测】

> **延迟口径（重要）**：以你们实测的 **0.195 ms/模块 @ 385 kMAC** 反推得 **0.506 ns/MAC**（原生标量 C），再按 MAC 数线性外推，v10 = 3249 模块。**这是标量口径**；int8 + 基线 SIMD 后通常还能再快 3–6×，但必须实测。
>
> **自洽性校验**：该模型预测 width8 CNN 全网格 = 195 µs × 3249 ≈ **634 ms**；你们报告约 70% 模块被门控跳过，则增量应为 0.3 × 634 ≈ **190 ms**，而你们实测 blur_shape 从 259 ms → 395 ms（**+136 ms**）。同一量级、略偏乐观，说明该外推口径可用（差异可由门控比例、缓存局部性、非模型开销解释）。

| # | 方案 | 模块准确率预期 | 端到端预期 | 延迟影响 | 模型体积 | 实现复杂度 | 建议 |
|---|---|---|---|---|---|---|---|
| **P1** | RS 擦除+GMD+CRC 列表 | 不变 | **+5～15 pt**（依赖 P3；oracle 上界见 2.4） | +1–5 ms | **0**（代码 <3 KB） | 中 | ✅ **立即做** |

# 6. 推荐三阶段路线

## 阶段 1（2–3 周，低成本、可快速证伪）

| 顺序 | 任务 | 产出 | Kill criteria |
|---|---|---|---|
| 1.1 | **E0 审计**：s 直方图、每块 (n,k)、每帧预算占用 U 分布 | 一张分布图 + 一个数字 | 无（必做） |
| 1.2 | **E1 oracle 擦除上界** | "RS 软判决天花板" | 提升 <3 pt ⇒ 砍 P1，转 P2/P10 |
| 1.3 | **E2 投影特征线性分类器**（P4） | 准确率 + µs/模块 | 比 width8 低 >1.5 pt ⇒ 转 P5 |
| 1.4 | **E3 可靠度 AUC**（P3 最小版） | margin vs 融合 AUC | 融合后 <0.80 ⇒ 先做 P10 |
| 1.5 | **E4 GMD+CRC 落地**（P1） | 端到端 + 耗时 | 真实提升 <2 pt ⇒ 回到 E3 |
| 1.6 | **E5 二值化成功分布统计 + 静态优先级**（P9 最小版） | 平均尝试次数 | top-3 命中 <85% ⇒ 只保留 ROI/早停 |

**阶段 1 的成功判据**：blur_shape ≥ 65%、eval ≥ 22%、真实照片 ≥ 6/13、**平均耗时不高于当前 259 ms（blur_shape）/53 ms（eval）**，且**模型层可默认开启**。

## 阶段 2（3–5 周，阶段 1 有收益后投入）

- **P5 rank16/32 的 Pareto 扫描** + int8 SIMD 内核（P11 必做部分）
- **P2 格式层改动**：A′ 免费对齐先上；短块/模块对齐做 A/B，与产品侧确认容量预算
- **P8 多帧模块级后验合并**（先测帧间不一致率）
- **P12 失败帧强制对齐数据引擎** + 屏拍噪声层参数校准
- **P7 的最小试探**（2 维条件特征）
- **P9 完整版**：ROI + 学习排序 + 早停

**阶段 2 成功判据**：blur_shape ≥ 75%、eval ≥ 30%、真实照片 ≥ 8/13，p95 耗时 <400 ms，默认 wasm <160 KB。

## 阶段 3（长期，3 个月+）

1. **KV/ASD 或 ORBGRAND 软判决**（P1 的理论上界版本）。**优先 ORBGRAND**：它只需要可靠度**排序**而非精确 LLR，与你们"置信度不准"的现实更匹配【论文 https://arxiv.org/abs/2202.13951】。
2. **P10 完整版**：运动模糊参数估计 + 容差引导搜索 + 正则化线性反演，对标 2026-10 的 93.1% 结果。
3. **编码-解码联合优化**：把可解码性写进码面渲染（线宽/inset/色板间距），参考 https://arxiv.org/abs/2011.07815。**这是 LCC 作为自研格式最大的长期优势——你可以改信道，而不只是改接收机。**
4. **格式层再设计**：形状层专用符号字母表 + 层内自适应冗余（按层可靠度分配 RS 预算）。
5. **可选 WebGPU 加速分支**：仅当 iOS Safari 正式支持后再评估（今天不支持）。

# 7. 明确"不值得再做"的方向

| # | 方向 | 理由 |
|---|---|---|
| 7.1 | **继续做 finder 热图 CNN / 更大的检测网** | 你们已实测：16.7%→16.7%，4/13→4/13，耗时 53→64 ms，**零 rescue**。且失败点在 finder 之后。**除非 E0/E1 显示存在"检测召回缺失"的帧，否则不碰。** |
| 7.2 | **任何像素级 SR（含用 C 残差重训的 SR）** | 你们已证伪两次。更根本的理由：【本地实验】brutal 桶所有方法都接近随机 ⇒ 信息已丢失，SR 只能"编"出像素；而 2026-10 的 QR 论文用**参数化 grey-box 93.1% 打败微调去模糊网 83.6%**，说明**正确的方向是参数估计+反演，不是像素回归**。 |
| 7.3 | **diffusion / flow / 一步扩散去模糊** | SinSR/OSEDiff/TinySR 即使一步也是 10⁸–10⁹ MAC/图，比你们整个解码器贵 1–2 个数量级；且优化目标是观感不是 payload。 |
| 7.4 | **默认走 WebGPU / WebNN** | 【工程】WebNN 至今 Chrome flag-only、Safari/Firefox `false`；WebGPU 在 iOS Safari `n`。扫码是"必须能用"的功能，不能建立在 flag 上。 |
| 7.5 | **端到端单应性回归网络** | LCC 有 3 finder + alignment + timing，**几何是超定且可验证的**；用网络回归 8 个参数既不可验证又不可解释，失败时无法诊断。正确形态是 P10 的"经典初值 + 可验证精修"。 |
| 7.6 | **模块级 Transformer / Mamba / MLP-Mixer** | 16×16=256 token 上，注意力/SSM 的开销远超收益；Mixer 的 token-mixing 在此退化为一个 256×256 线性层，**不如直接用 rank16 投影（P5）**。【本地实验】线性模型已达 85–89%。 |
| 7.7 | **在 P4/P5 之前继续压 CNN 的 width（6/4）** | 你们 width8 是 385 kMAC；P4 是 1.6 kMAC。**先把算子换掉，再谈压缩**。压 width 到 4 最多再省 4×，仍比 P4 贵 60×。 |
| 7.8 | **Hann/高斯加窗抑制邻域串扰** | 【本地实验·新负结果】M1w 在所有桶上都比不加窗差（easy 54.3% vs 77.9%）。加窗削掉了笔画端点证据。 |
| 7.9 | **单帧去摩尔纹网络** | 摩尔纹与采样栅格乘性耦合，单帧去纹会同时破坏笔画高频。RAW 域方法在浏览器拿不到 RAW。**改用多帧 + 频域陷波 + 早停**。 |
| 7.10 | **依赖 ONNX Runtime / 任何外部推理运行时** | 违反约束，且体积/启动成本不可接受。 |
| 7.11 | **默认开启每帧 TTA** | SAR 明确指出小 batch/混合偏移下 TTA 会变差；你们只有单帧、13 张真实验证样本，**统计功效不足以证明安全**。做成可选、限幅、CRC 失败回滚。 |

# 8. 下一步实验的详细 Protocol

## 8.1 如果只能再做一个实验

> **做 E1：oracle 擦除上界实验。**
>
> 用合成数据已知的 payload 反推真值模块矩阵，标出每个模块的对错，把错误模块作为**擦除**喂给现有 RS（errors-and-erasures），跑 240 帧 eval + 240 帧 blur_shape + 13 张真实照片（真实照片无真值，用"解出来的帧"做 leave-one-out 一致性检验或跳过）。
>
> **一天内完成，不需要训练任何模型，不需要改前端。** 它输出的一个数字（端到端上界）直接决定：整个"RS 软判决 + 可靠度"方向（P1+P2+P3，占本报告推荐工作量的一半）值不值得投。
>
> 如果上界很高（例如 blur_shape 44.6%→80%），说明**信息还在，只是被硬判决浪费了** —— 这是最好的结果。  
> 如果上界也很低（<50%），说明**信息真的丢了**，必须转向 P2（格式）或 P10（几何/模糊），而不是继续做分类器。

## 8.2 数据集与划分

| 集合 | 内容 | 用途 | 注意 |
|---|---|---|---|
| **D-clean** | 干净轴对齐 240 帧 | 回归护栏 | **任何改动不得使其低于 99.6%** |
| **D-eval** | 相机退化 240 帧（难度 0–1） | 主指标 | 按难度分层报告 |
| **D-shape** | blur_shape 240 帧 | 形状层主指标 | 同上 |
| **D-resid-train** | 现有 367,755 个 C 残差（180 帧） | 训练 | **按帧划分，不按模块划分**（同帧模块高度相关，按模块划分会严重高估） |
| **D-resid-fail**（新） | 60 个失败帧强制对齐残差 | 难尾训练/评估 | 需新增导出 API |
| **D-real** | 13 张真实照片 | **仅验证，绝不训练** | 样本量太小，只能做定性 rescue case 分析 |
| **D-real-burst**（新，建议采集） | 同一码面 5 连拍 × 20 个场景 | P8 多帧验证 | 真实照片不参与训练，但可以采集更多用于**验证** |

**划分原则（关键）**：
- **按帧/按码面划分**，train/val/test = 60/20/20，**同一码面不得跨集**。
- 难度分层：按合成器的退化参数把帧分成 4 层，**每层单独报告**，避免平均值掩盖难尾。
- 固定随机种子，划分文件入库。

## 8.3 指标定义（必须全部报告）

**主指标**
1. **端到端 payload 完全一致率**（逐集合、逐难度层）
2. **每帧 RS 预算占用** `U = (e + 2·t_used)/(n−k)` 的分布：中位、p75、p90、`P(U≤1)`
   - 这是**唯一能预测端到端的模块级指标**（见 2.3）

**模块级**
3. 8 分类准确率（**逐帧分布**，不只平均值）
4. **错误检测 AUC**（可靠度对"是否错"的判别力）← 决定 P1 收益
5. **ECE**（期望校准误差）+ risk–coverage 曲线
6. **cap@k%**：擦除最低置信 k% 时捕获的错误比例（k=5,10,15,20），随机基线 = k%

**检测/几何**
7. finder 三中心齐全率（9 px 内）+ 平均中心误差
8. **网格对齐误差**：采样中心与真值模块中心的像素距离分布（用强制对齐得到）

**系统**
9. 平均 / 中位 / **p95** 耗时，**成功路径与失败路径分开统计**
10. 二值化平均尝试次数、模型调用模块数、RS 解码尝试次数
11. `lcc.wasm` 体积（默认/模型版）、WASM 峰值内存、冷启动时间

## 8.4 基线（每个新方案都必须同时对比）

| 基线 | 说明 |
|---|---|
| B0 | 当前 C 模板匹配（默认路径） |
| B1 | 16×16 双线性 + \|NCC\| |
| B2 | 经典 finder 检测（不带 CNN） |
| B3 | 多帧 canonical 像素叠加 |
| B4 | width8 CNN（96.1%，0.195 ms/模块）+ 现有门控 |
| B5 | **随机可靠度的 GMD**（用于隔离"擦除机制本身"与"可靠度质量"的贡献） |

**B5 很重要**：如果 P1 的提升在 B5 下也出现，说明收益来自"多档尝试"而非可靠度，那 P3 的优先级要下调。

## 8.5 消融矩阵（区分检测/形状/颜色/RS 的收益）

用 **2⁴ 因子设计**（16 组），每组固定其他三项为基线：

| 因子 | 关 | 开 |
|---|---|---|
| G 几何 | 现有 H | +P10 精修 |
| S 形状 | B0 模板 | +P4/P5 |
| C 颜色 | 现有校准 | +P7 条件特征 |
| R 纠错 | errors-only | +P1 GMD+CRC（配 P3 可靠度） |

**报告主效应与交互效应**。我的【推测】：**R 的主效应最大，S 次之，G 在 eval 上大于在 blur_shape 上，C 最小**；且 **R×S 有强交互**（形状更准 → 可靠度更准 → 擦除更有效）。这个矩阵能直接证伪或证实它。

**额外的"归因消融"**：对每个失败帧，记录**第一个不可恢复的失败点**（finder / 版本估计 / 格式带 / 颜色校准 / 符号错误超预算 / CRC 失败），做成失败模式直方图。**这张图比任何准确率都更能指导下一步。**

## 8.6 统计显著性

- **端到端率**：240 帧，配对设计 ⇒ 用 **McNemar 精确检验**（同一帧在两个方案下的解/不解），报告 p 值与 **odds ratio + 95% CI**。
  - 240 帧下，**+5 pt（12 帧）的差异 McNemar 通常在 p<0.05 边缘**；**+3 pt 基本不显著**。**不要根据 +2 pt 就下结论。**
- **率的置信区间**：用 **Wilson score interval**，不要用正态近似（p 接近 0/1 时会失效）。
- **模块准确率**：367k 模块看似样本量大，但**同帧模块强相关** ⇒ 必须用 **按帧 bootstrap（cluster bootstrap）**，重采样帧而非模块。有效样本量是 **180 帧，不是 367k 模块**。这是最容易犯的统计错误。
- **耗时**：报告 **中位 + p95**，用 **paired bootstrap**；同一机器、同一浏览器、固定 CPU 频率策略，每次跑 ≥30 帧取分布。
- **真实照片 13 张**：**只做定性 rescue case 记录**（哪张从失败变成功、失败点如何变化），**不报告百分比差异的显著性**（n=13，+1 张 = +7.7 pt，毫无统计功效）。
- **多重比较**：消融矩阵 16 组 ⇒ 用 **Holm–Bonferroni** 校正。

# 9. 对你 26 个具体问题的直接回答

## A. 模块级形状识别

**A1｜除普通 CNN 外更适合的结构化分类器**  
排序（依据【本地实验】）：**① 低秩白化 + 学习原型（P5，89.3%/85.7%）② 投影特征 + 线性判别（P4，76.0%/43.9%，最便宜）③ 子空间 GLRT / 稀疏表示（P6，免训练但不如学习版）**。  
prototype/metric learning **值得**（8 类 + 已知模板 = 原型可解析初始化，小样本友好）；template learning **最值得**（就是 P5）；deformable template **值得但只在参数少的方向**（线宽/inset/相位，不要上 DCN）；sparse representation **退化成 5 原子 NNLS 才划算**；low-rank **就是 P5 的核心**；Graph/Transformer/MLP-Mixer/SSM **不值得**（见 7.6）。

**A2｜形状+颜色联合建模**  
**值得，但先做 1% 成本的试探**：给形状分类器加"对比度符号 + 幅度"两维条件特征。理由：形状判别的符号歧义、颜色背景估计的偏差，二者互为噪声（P7）。若试探 <0.5 pt 就放弃完整版。

**A3｜如何利用已知结构做 inductive bias**  
四条，按性价比：  
① **8 形状 = 5 笔画原子的子集族**（`X=/+\`，`+=-+|`）⇒ 子空间/稀疏编码（P6）；  
② **方向性**⇒ 行/列/对角投影，且投影与模糊可交换、能平均噪声（P4，**最有效**）；  
③ **线宽/inset 随模块尺寸变化**⇒ 作为显式 nuisance 参数进 bank，或让线性层从多尺寸训练数据里自己吸收；  
④ **前景/背景对比方向**⇒ 作为条件特征而不是让分类器盲猜（P7）。

**A4｜置信度/erasure 如何与 RS 软判决结合**  
`模块后验 → 校准 → 符号可靠度（取该符号涉及模块的最小可靠度）→ 排序 → GMD 多档擦除 → errors-and-erasures RS → CRC32 选码字`。  
**关键**：【本地实验】AUC<0.8 时擦除几乎无收益；必须融合几何/模糊/颜色信号（P3）。进阶：KV/ASD 用重数矩阵，或 ORBGRAND 只用排序（对不准的置信度更稳健）。

**A5｜active learning / domain adaptation / TTA**  
- **active learning：可行且高性价比** —— 用"预算占用 U 接近 1 的帧"作为采集准则（这些帧最可能翻盘），比随机标注高效得多。  
- **domain adaptation：首选"用 C 实际残差训练"**（你们已在做，这就是最直接的 DA）；其次是失败帧强制对齐（P12）。  
- **TTA：可行但默认关闭**。只更新增益/偏置/白平衡等 2–4 个标量，限幅 + CRC 失败回滚。SAR 论文证明单帧/混合偏移下 TTA 会变差。

## B. 超分/去模糊

**B1｜任务感知 SR / deblurring / unrolled / PnP / diffusion 的实际收益与成本**  
【论文】最直接的证据是 2026-10 的 QR 工作：**参数化 grey-box 93.1% > 微调去模糊网 83.6%**（955 张真实手机照片）。场景文字 SR 领域也早已确认**像素指标与识别率脱钩**。diffusion 即使一步蒸馏也是 10⁸–10⁹ MAC/图，**不可行**。unrolled/PnP 的迭代次数 × 网络成本在 WASM 上不可接受，**除非展开成 5–8 个线性层**（那时它就变成了 P5/P6）。

**B2｜是否放弃像素 SR**  
**是。** 改成"**分类前的轻量增强**"（其实就是 P4 的投影 = 一种 learned pooling）或"**可学习的模板匹配**"（P5）。【本地实验】这两者在同一观测域上比模板 NCC 高 26–36 pt，且便宜 40–245×。

**B3｜若坚持 SR，训练目标该是什么**  
优先级：**下游 RS 成功 > 分类交叉熵 > NCC > 边缘 > 像素 L2**。但**端到端可微解码不可行**（RS 不可微）。可行的替代是 **"可微分类器 + 冻结的 RS 预算代理损失"**：用 `soft budget occupancy` 作为损失（可微的 sigmoid 近似 `e+2t ≤ n−k`）。【推测】这比像素 L2 好，但**仍然不如直接训分类器**——因为 SR 的中间表示是多余的。

**B4｜WASM 里 SR 的算力上限；哪些架构值得**  
【解析】以你们 0.195 ms/模块 @385 kMAC 反推 ≈ **2 GMAC/s** 标量 C。若目标是"整帧形状层 <30 ms"（v10 3249 模块），预算 ≈ **18 kMAC/模块**。SIMD 后可放宽到 ~100 kMAC/模块。  
⇒ **depthwise/separable 值得**（但仍比 P4 贵 10×）；**Winograd 不值得**（该换掉卷积而不是加速它）；**DCN 不值得**（动态索引在 WASM 上代价高）；**小波值得考虑**作为廉价特征（2 级 Haar = 几次加减，可替代投影特征的一部分）。

## C. Finder / 几何

**C1｜轻量检测/关键点/分割/heatmap/regression 的取舍**  
对 1:2:1:2:1 自定义 finder，**经典径向剖面 + 连通域仍是最优性价比**（你们已验证 CNN 无 rescue）。若一定要学，**学"验证器"而不是"检测器"**：输入 32×32 候选 patch，输出"是不是真 finder"的二分类（<1 k 参数），用来剪掉假阳性，**比热图网络便宜 30×**。分割/回归都不合适（finder 是高度结构化的同心环，参数化描述比像素描述更紧凑）。

**C2｜finder+alignment+timing+单应性端到端小网**  
**不建议**。代价：不可验证、失败不可诊断、需要大量几何标注。风险：LCC 的几何本来超定可解，用网络是把确定性问题变成统计问题。**正确形态是 P10**。

**C3｜摩尔纹/运动模糊/遮挡下，经典检测+学习验证/修复 vs 纯学习检测**  
**经典检测 + 学习验证更划算**【推测，但与 EgoQR/ADNet 的工程路线一致】。理由：经典检测在简单帧已成功（你们的数据），难帧的问题在后级；学习验证只在候选上跑，成本可控。摩尔纹建议**频域陷波 + 多帧**，不做单帧去纹网络。

**C4｜如何利用几何约束做可微/可验证优化**  
3 finder + 1 alignment = 8 约束 vs 单应性 8 自由度 ⇒ 恰定；**加 timing 行/列后变成超定** ⇒ 可做：  
① RANSAC 式一致性检验 → 输出几何可靠度（喂 P3）；  
② inverse-compositional LK 在 timing 上精修 H（P10）；  
③ 用重投影残差作为**早停判据**（残差过大直接放弃该分支）。

## D. 解码器系统优化

**D1｜12 种二值化能否预测/排序/剪枝**  
**能，且先做免费的**：统计 240 帧上成功变体的分布，若集中在少数几种，**静态重排序即可**（零模型）。再进一步用 20 维整帧统计训一个排序器（P9）。保留回退全扫，但按 ROI 质量决定回退深度。

**D2｜哪些重复计算可以复用**  
① 12 种变体共享**同一份灰度图/积分图**（如果现在每种都重建，这是最大的浪费）；  
② finder 检测一次 → H 一次 → **网格采样一次**，12 种变体不应各采一次；  
③ 形状残差与颜色校准共享**同一次 warp 采样**；  
④ 投影特征的行/列和可以**在整张网格图上一次性算完**，而不是每模块重算；  
⑤ RS 的 GF 表、syndrome 计算在多档 GMD 间可复用（擦除只改定位多项式，syndrome 不变）。

**D3｜ROI 检测 + 局部解码是否值得**  
**值得**【论文：EgoQR 自报 +34%】。整帧多假设的成本是 O(12 × 全图)，ROI 后是 O(12 × ROI)。对手机照片（码面常占 <20% 画面）收益显著。

**D4｜多帧下置信度/erasure/跨帧对齐/RS 软信息如何结合**  
见 P8。**关键三点**：① 融合在**后验层**而非像素层；② **F=2 是陷阱**（不一致率吃满擦除预算），F=3 起才有效；③ 跨帧对齐必须亚模块级，且要做**帧间多样性检验**（不一致率 <3% 说明帧太相似，合并无益）。

**D5｜失败路径如何早停**  
用 P3 的可靠度算**预测预算占用 Û**；【本地实验】2.3 的分布表明 p>15% 的帧救不回来。规则：`Û > 1.5` 且几何残差正常 ⇒ 放弃模型与多档 RS，直接返回失败。**阈值必须离线校准到误杀率 <0.5%。**

## E. 高效推理

**E1｜WASM SIMD 下最值得手写的算子**  
排序：**① int8 GEMV（P5 的 256×32 投影）② 投影累加（P4 的行/列/对角）③ popcount（二值模板）④ GF(256) 乘法（RS 多档）**。  
im2col/Winograd/depthwise **都不该做**——因为正确的方向是**把卷积换成投影**。  
**关键工程事实**：int8 点积指令 `i32x4.dot_i8x16_i7x16_add_s` 属于 **Relaxed SIMD，Safari/iOS/Firefox 不支持**；必须用 `extmul → extadd_pairwise → i32` 基线路径，且注意 i16 累加只能安全放 2 项。

**E2｜Pareto 前沿大概在哪**  
【本地实验 + 解析】三个点：  
- **极致廉价**：P4，0.6 KB / 1.6 kMAC / ~0.8 µs/模块，准确率≈width8；  
- **平衡点（推荐）**：P5-rank16，4.5 KB / 4.5 kMAC / ~2.3 µs/模块，准确率≈width16；  
- **上限**：width8 CNN，1.3 k 参数但 385 kMAC / 195 µs/模块 —— **它在 Pareto 前沿之外**（参数少但算力高，这是 CNN 在 tiny 输入上的典型陷阱）。

**E3｜WebGPU/WebNN 还是 WASM SIMD**  
**坚持 WASM SIMD。**【工程】WebNN 至今 Chrome flag-only、Safari/Firefox `false`；WebGPU iOS Safari `n`、Safari 桌面 flag/almost。基线 SIMD 支持率 96.78%。WebGPU 分支的启动成本（shader 编译 + 管线创建）通常 10–100 ms，**对单帧扫码是净亏损**，只有连续扫描才可能摊薄。**阶段 3 再评估。**

**E4｜width 6/4、二值化、查表是否可行**  
可行，**但顺序错了**。先把算子从 CNN 换成投影/低秩（省 40–245×），再谈压 width（最多再省 4×）。二值化（`i8x16.popcnt` 全平台可用）和查表（PolyLUT/NeuraLUT/TreeLUT 思路）在 8 类低维特征上确实可行，**但收益是边际的**，且树模型在 WASM 上分支密集，**必须实测不要假设**。

## F. 数据与评估

**F1｜如何构造 C 实际残差训练集（含失败帧）**  
新增 `lcc_export_residuals_forced`：用已知 payload + 版本反推真值模块矩阵 → 即使解码失败也强制建立网格 → 导出残差 + 标签 + 辅助信号。**这是你们相对通用 CV 任务的独有优势（合成数据 payload 已知 = 免费标注），目前没用满。** 真实域偏移用"测真实照片的退化参数分布 → 校准合成器"来缩小，而不是用真实照片训练。

**F2｜哪些增强真正对应手机失败模式**  
见 P12 的 7 条排序。**最重要的两条是"亚像素相位/局部单应性微偏"和"邻域串扰"** —— 后者正是你们独立渲染训练集缺失、导致 SR 崩盘的根因。**最容易被过度随机化的是传感器噪声。** 另外**务必检查合成器是否模拟了 JPEG 4:2:0 色度下采样**——对彩色码这是致命退化。

**F3｜怎样的指标能预测端到端 RS 成功率**  
**每帧 RS 预算占用 `U=(e+2t)/(n−k)` 的分布 + `P(U≤1)`**，而不是平均模块准确率。【本地实验】2.3 证明：平均 96.1% 与端到端 57.5% 在重尾分布下完全自洽。辅助指标：**错误检测 AUC**（决定擦除收益）、**cap@10%**、**ECE**。

**F4｜如何做消融区分四类收益**  
2⁴ 因子设计（G/S/C/R）+ 主效应/交互效应 + **失败模式归因直方图** + **B5 随机可靠度对照**（隔离"多档机制"与"可靠度质量"）。详见 8.5。

## B. 关键 C 代码骨架

### B.1 GMD + CRC 列表选择（P1）

```c
/* 前置：reliability[] 已按符号聚合（取该符号涉及模块的最小可靠度）
   erase_order[] 已按可靠度升序排好。syndrome 只需算一次。 */
int lcc_rs_decode_gmd(uint8_t* blk, int n, int k,
                      const uint16_t* erase_order, int max_trials,
                      uint32_t crc_expected, LccRsStats* st)
{
    const int nk = n - k;
    uint8_t work[256];
    uint8_t synd[64];
    memcpy(work, blk, n);
    rs_syndrome(work, n, k, synd);              /* 复用：擦除不改 syndrome */
    if (rs_is_zero(synd, nk)) {                 /* 0 档：本来就对 */
        if (lcc_crc32_ok(work, k, crc_expected)) return 0;
    }
    /* 档位按 "预期最可能成功" 排序，而不是 0,2,4,...  */
    static const int frac[] = {6,10,14,18,22,26,30,32};  /* 占 nk 的百分比 */
    for (int t = 0; t < max_trials; ++t) {
        int e = nk * frac[t % 8] / 100;
        if (e & 1) e++;                          /* 保持偶数，便于对齐 */
        if (e > nk) break;
        memcpy(work, blk, n);
        rs_decode_erasures(work, n, k, synd, erase_order, e);  /* BM 用擦除定位多项式初始化 */
        st->n_rs_trials++;
        if (lcc_crc32_ok(work, k, crc_expected)) {
            memcpy(blk, work, n);
            st->hit_erase_count = e;
            return 0;                            /* 早停：CRC 通过立即返回 */
        }
    }
    return -1;
}
```

### B.2 投影特征（P4），行/列/对角，SIMD 友好

```c
/* res: 16x16 int8 残差；out: 68 维 int16 特征 */
void lcc_proj_features(const int8_t* res, int16_t* out)
{
    int16_t diag[31] = {0}, anti[31] = {0};
    /* 行/列：连续访存，直接 SIMD 累加 */
    for (int y = 0; y < 16; ++y) {
        const int8_t* row = res + y*16;
        int32_t rs = 0;
        for (int x = 0; x < 16; ++x) {
            rs += row[x];
            diag[y - x + 15] += row[x];
            anti[y + x]      += row[x];
        }
        out[y] = (int16_t)rs;
    }
    for (int x = 0; x < 16; ++x) {
        int32_t cs = 0;
        for (int y = 0; y < 16; ++y) cs += res[y*16 + x];
        out[16 + x] = (int16_t)cs;
    }
    /* 31 -> 16 线性重采样（预计算索引/权重表） */
    resample31to16(diag, out + 32);
    resample31to16(anti, out + 48);
    /* 4 个环带能量：预计算掩码，点积 */
    for (int b = 0; b < 4; ++b) out[64 + b] = band_energy(res, b);
}
```

### B.3 int8 GEMV，基线 WASM SIMD（无 Relaxed SIMD 依赖）

```c
/* y[r] = sum_c W[r][c] * x[c]，W int8，x int8，累加到 int32。
   关键：int8*int8 的积在 i16 中只能安全累加 2 项，必须立刻 widen 到 i32。 */
#include <wasm_simd128.h>
static inline int32_t dot_i8(const int8_t* w, const int8_t* x, int n)
{
    v128_t acc = wasm_i32x4_splat(0);
    for (int i = 0; i < n; i += 16) {
        v128_t a = wasm_v128_load(w + i);
        v128_t b = wasm_v128_load(x + i);
        v128_t lo = wasm_i16x8_extmul_low_i8x16_s(a, b);   /* 8 个 i16 积 */
        v128_t hi = wasm_i16x8_extmul_high_i8x16_s(a, b);
        acc = wasm_i32x4_add(acc, wasm_i32x4_extadd_pairwise_i16x8_s(lo));
        acc = wasm_i32x4_add(acc, wasm_i32x4_extadd_pairwise_i16x8_s(hi));
    }
    return wasm_i32x4_extract_lane(acc,0) + wasm_i32x4_extract_lane(acc,1)
         + wasm_i32x4_extract_lane(acc,2) + wasm_i32x4_extract_lane(acc,3);
}
```

### B.4 子空间 GLRT 打分（P6），每档只需 5 次点积

```c
/* bank[b]: Q[256][5] int8, M[8][5][5] int16, 全部离线预计算 */
for (int b = 0; b < NB; ++b) {
    int32_t u[5];
    for (int j = 0; j < 5; ++j) u[j] = dot_i8(bank[b].Q + j*256, res, 256);
    for (int h = 0; h < 8; ++h) {
        int64_t e = 0;
        for (int i = 0; i < 5; ++i)
            for (int j = 0; j < 5; ++j)
                e += (int64_t)u[i] * bank[b].M[h][i][j] * u[j];
        int32_t sc = (int32_t)((energy - e) >> SHIFT) + LAM * hyp_size[h];
        if (sc < best[h]) best[h] = sc;
    }
}
```

## 结语：一句话总结

> **你们已经把"看得见"的问题解决得差不多了，剩下的是"算得准"的问题。**  
> 在 LCC 这种结构化符号信道上，**把 1 份算力花在 RS 的擦除/软判决上，回报大约是花在 CNN 上的 3000 倍**；而形状层真正需要的不是更强的网络，而是**在正确观测域上训练的、只有几百个参数的线性判别器**。  
> 先做 E0 审计和 E1 oracle 上界这两个一天级的实验 —— 它们会告诉你，剩下的收益到底在信道侧还是在模型侧。
