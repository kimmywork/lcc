# LCC 实验状态与路线（2026-11-11）

> 范围：只优化会被扫描识别的 **基础层 + 8 符号层**。C60/C80 和 32 符号层（G15/G25/G35/C25/C35/C45/C55/C65/C85）按数字/打印 profile 处理，不进入扫描优化队列。
> 默认路径：shape 层使用 **C 实际残差训练的 width8 分类器 + 模板门控**；有效模块 <12 px 时回退模板。finder/SR/bilinear/abs/MLP 已从生产路径移除。

---

## 1. 当前默认

- shape 层：width8 形状分类器 + 16×16 模板门控；模块有效尺寸 <12 px 时回退模板。
- 非 shape 层：经典模板/颜色分类。
- 32 形状层：解析模板，不使用分类器。
- 扫描失败后：gray-world 白平衡重试 → 单帧全解码回退（前 10 个透视变体）。
- 默认 `lcc.wasm` 约 211 KB；不再有模型版/feature 开关。

**已移除**：finder CNN、SR CNN、双线性+abs、形状 NCC 取绝对值、cheap MLP、小卷积 stem。

---

## 2. 做过的实验与结论

### 2.1 基线

| 数据 | 结果 |
| --- | ---: |
| 干净轴对齐 240 帧（60 帧抽测） | 98.3% |
| 相机退化 eval 240 帧 | 26.3% / 416 ms |
| 轴对齐退化形状层 blur_shape 240 帧 | **56.7% / 369 ms** |
| 真实照片 13 张 | **9/13 / 2.59 s（失败帧回退；成功帧仍快）** |

历史基线（仅模板）：eval 16.7% / 53 ms，blur_shape 44.6% / 259 ms，真实 4/13。

### 2.2 Finder CNN

- 192×192 灰度 → 48×48 中心热图，22k 参数，30.6 MFLOP/帧。
- 验证集三中心 9 px 内齐全率 40.3%。
- 接进 C 后：eval 16.7% → 16.7%，真实照片 4/13 → 4/13，平均 53 → 64 ms。
- **结论：无效，已移除。**

### 2.3 SR CNN

- 16×16 残差 → 32×32 残差，5k 参数，2.73 MFLOP/模块。
- 合成模块数据：普通 99.4%，强退化 31.6%。
- C 实际残差上：83.3%，不如双线性 87.9%，更不如 C 模板 91.3%。
- 端到端 blur_shape 60 帧：51.7% → 13.3%，280 ms → 5.8 s。
- **结论：无效，已移除。**

### 2.4 C 实际残差 + 形状分类器（当前默认）

- 新增 `lcc_api_debug_residuals`，从真实解码链路导出 16×16 输入。
- 367,755 个模块 / 180 帧。
- width8 CNN：96.1% 模块准确率；width16：97.0%。
- 端到端 blur_shape：44.6% → 56.7%；真实照片 4/13 → 9/13（含白平衡/全解码失败回退）。
- 模板门控约 70% 模块可跳过网络。
- **结论：有效，作为默认 shape 层路径；模块 <12 px 时回退模板。**

### 2.5 强制对齐残差

- 新增 `lcc_api_debug_residuals_h`，用已知 H/version/N/moduleSize 直接走 `decode_found`。
- eval 240 帧拿到 48 帧 / 102,884 个模块；其中 30 帧是 8 形状层，47/48 是 RS 失败帧。
- 合并难尾后：
  - width8：base 96.13% → 95.96%，forced 19.58% → 21.20%；
  - cheap MLP：base 96.33%，forced 28.41%。
- **结论：数据引擎有效，能改善模块级难尾；但真实照片仍不够。**

### 2.6 Cheap MLP

- `abs(16×16) + 68 维投影` → 324 → 64 → 8，约 21k MAC/模块，是 width8 的 1/18。
- base val 96.3%，forced val 28.4%。
- 端到端 blur_shape 34/60 = 56.7%，平均 233 ms。
- 真实照片 **2/13**，width8 是 5/13。
- **结论：算力便宜成立，真实域泛化不够，已从生产路径移除。**

### 2.7 小卷积 stem

- 1→8→16，global avg+max，约 56k MAC/模块。
- 合并数据：base 92.9%，forced 18.4%。
- **结论：不如 cheap MLP 和 width8，已移除。**

### 2.8 32 形状富符号层

- 新增 `L3u`（32 色 + 32 形状，10 bit）、`L4eS`（64 色 + 32 形状，11 bit）、`L4fS`（256 色 + 32 形状，13 bit）。
- 格式带用 `shapeExt` 位映射，不需要新格式。
- JS/C 轴对齐 round-trip、轻度透视 round-trip 通过；tests 23/23。
- **结论：数字/打印 profile 可用；不进入摄像头扫描优化。**

### 2.9 RS 打包审计

实测 `s`（每个模块平均触及多少个 RS 字节）：

| 层 | bit/模块 | s |
| --- | ---: | ---: |
| L1 | 1 | 1.00 |
| L2a | 2 | 1.00 |
| L2b | 3 | 1.25 |
| L3b | 3 | 1.25 |
| L3c | 4 | 1.00 |
| L3d | 5 | 1.50 |
| L3s | 6 | 1.50 |
| L3t | 7 | 1.75 |

审计脚本已在最终清理中移除；结果保留在这里作为历史依据。
**结论：L1/L2a/L3c 最适合做 erasure；L3s/L3t 成本更高；L4/32 形状层不参与。**

### 2.10 E1 oracle erasure

- 曾用 `lcc_api_debug_residuals_h_symbols` 导出 C 实际符号；该 E1 专用 API/脚本已在最终清理中移除。
- 修掉 `synth.augment` 的 Hinv 归一化 bug 后，131 个强制对齐帧里 **130 帧布局一致**。
- 硬判决 pass：20/130；oracle erasure pass：26/130。**只多救 6 帧**。
- 大多数失败帧即使 oracle erasure，Uora 仍在 2–5，属于灾难性丢符号，不是“差几个符号”。
- **结论：至少在这批硬帧上，失败是灾难性的，不是“差几个符号”；RS erasure 不是当前首选。**

### 2.11 真实照片剩余 4 张归因

| 照片 | 场景/层 | 几何 | 符号错误 | 主要问题 | 结论 |
| --- | --- | --- | ---: | --- | --- |
| `224710` | 屏幕，L3s v8/N49 | 正常 | payload 未确认 | 屏幕纹理/反光，码面在 UI 中 | 低价值 |
| `224801` | 打印，L2s v2/N25 | 正常 | 33.8% | 眩光/模糊压缩灰阶 | 信息大概率已丢 |
| `224813` | 屏幕，L3s v5/N37 | 正常 | 12.3%（115 shape + 8 color） | 形状错为主，屏幕摩尔纹/反光 | 唯一有理论可能 |
| `224805` | 打印/裁切 | no finder triple | — | 构图不完整 | 低价值 |

对 `224813` 试过：高斯 blur 0.8–12 px、中值 3/5/7/9、局部对比度归一化、低通 high-pass、降采样 0.5/0.35/0.25 再放大、blur+contrast；**全部无法解出**。  
结论：简单屏幕去纹/反光抑制不足以把形状错误从 12.3% 压到 RS 可解范围；`224801` 的灰阶信息损失更严重；`224710/224805` 缺 payload/构图不完整。**9/13 作为当前停点。**

### 2.12 命名迁移与完整层矩阵

层名改为直接编码两个维度：

- `G<色彩位宽><符号位宽>`：灰度；
- `C<色彩位宽><符号位宽>`：彩色。

完整矩阵共 27 层：9 个灰度层（G10/G13/G15/G20/G23/G25/G30/G33/G35）和 18 个彩色层（C20/C23/C25/C30/C33/C35/C40/C43/C45/C50/C53/C55/C60/C63/C65/C80/C83/C85）。新增层包括 G25、G33、C2*（4 色 + 无/8/32 符号）、C35、C45、C53、C63、C83。旧 `L*` 名称全部保留为 alias，映射见 README 与 `docs/lcc-spec.md`。

格式层码为 `(shapeExt, palette, seed低2位)`，variant 0 保留原有 8 个 shape 层码；完整表见规范附录 A。形状层固定白化 seed 0；旧版本以非零 seed 写出的形状码不兼容，需要重新生成。由于新增 4 色/8 色/更高符号层，palette 表从 25 组增至 45 组，`lcc.wasm` 约 211 KB。

验证：所有 27 层 JS 编码 + C wasm 解码 round-trip 通过；Web UI 改为按“灰度/彩色、色彩数、符号数”选择；`npm test` 25/25。

## 3. 最终状态

### 保留并生效

1. **C 实际残差训练的 width8 形状分类器 + 16×16 模板门控**：默认 shape 层路径；模块 <12 px 回退模板。
2. **失败回退**：gray-world 白平衡重试 → 单帧全解码（前 10 个透视变体）。
3. **32 符号富符号层**：G15/G25/G35/C25/C35/C45/C55/C65/C85，数字/打印 profile。
4. **强制对齐数据引擎**：用于生成与 C 实际链路一致的训练/难尾残差。

### 已证伪并移除

1. Finder CNN（无 rescue，慢）。
2. SR CNN（C 残差上更差，慢）。
3. 双线性 + abs NCC、形状 NCC 取绝对值（端到端无增益）。
4. Cheap MLP（真实 2/13，域泛化不足）。
5. 小卷积 stem（92.9/18.4，不如 width8）。
6. 几何/timing 全局精修（真实 5/13 → 3/13，净负）。
7. RS erasure（E1 oracle 只多救 6/130 帧，收益不足）。
8. 屏幕去纹/反光抑制（224813 全部预处理无解）。
9. 所有 feature 开关、模型版构建、finder/SR/MLP 训练脚本和 E1 专用导出 API。

### 后续可选（未安排，不属于当前路线）

以下方向仍有理论价值，但当前产品阶段不投入：

- 编码侧：相机 profile、Gray 映射、亮度/色度分离、校准图案的端到端 A/B。
- 多帧：模块级 F=3 后验融合，需要更多真实连拍验证。
- 推理：int8 + 基线 WASM SIMD 加速 width8 分类器。
- 检测：两阶段经典候选 + 局部 verifier，仅在出现明确 finder 漏检样本时再做。
- 屏幕/打印：只在有新的、构图完整、payload 已知的样本上重开；不再针对现有 4 张调参。

---

## 4. 收尾结论

- 扫描优化停在 **9/13 真实照片**。
- 当前默认 wasm 约 **211 KB**，无 feature 开关。
- 识别率：clean 98.3%（60 帧抽测）、eval 26.3%、blur_shape 56.7%、真实 9/13。
- 速度：成功帧仍在 240 ms 量级；失败帧会走深扫描回退，真实失败帧约 1.3–13 s。
- `npm test` 23/23。
- 除非有新的真实难例或产品需求，不再继续模型/预处理堆叠。
