# LCC — Layered Chromatic Code 规范 v0.1

> 状态：参考实现（Phase A 清洁数字链路 + Phase B 摄像头透视/色偏链路）。
> 本规范取代并删除旧的 HLC（Hexagonal Layered Code）六边形设计稿。
> 代码实现：`src/`；Web 版：`docs/`；示例：`examples/`。

---

## 1. 命名与范围

LCC 是一套**方形、分层、按信道能力换符号表**的二维图形码：

| 层 | 符号表 | 名义 bit/模块 | ECC | 典型信道 |
| --- | --- | --- | --- | --- |
| **L1** | 2 态黑白 | 1 | 20% | 任何信道兜底 |
| **L2** | 16 级等 L\* 灰 | 4 | 35% | 屏幕 + 打印 |
| **L3a** | 64 色（近似 CMYK 色域） | 6 | 40% | 打印 / 屏幕保守档 |
| **L3b** | 256 色（sRGB） | 8 | 40% | 屏幕 / 摄像头 |

L1/L2/L3a/L3b 共用同一套方形几何、定位图案、格式带和校准枢纽，只替换符号映射。
24bit 真彩的 File Mode 是**独立数字承载模式**，不进入本分层表，后续单独实现。

---

## 2. 几何与动态尺寸

- 方形模块，边长 `s` 像素，整数。
- 屏幕最小 `4px`，打印最小 `6px`；参考实现默认上限 `64px`。
- 版本 `v = 1..100`，符号边长（不含静区）：

```
N = 21 + 4 × (v - 1)
```

- 静区 `q = 2`（屏幕）/ `4`（打印）模块。
- 绘制边长：

```
(N + 2q) × s
```

- 两种选档模式：
  - **fill（默认）**：从最大 `s` 向下试，取能放下载荷的最大模块尺寸，让码面尽量铺满画布。
  - **compact**：选能放下载荷的最小 `N`，再取最大 `s`，居中留白。
- 版本 `N` 不写入格式带，由定位图案中心距和定时图案推导。

## 3. 码面布局

### 3.1 定位图案（finder）

- 3 个，位于左上、右上、左下。
- 7×7 同心方环，剖面比例 **1:2:1:2:1**：

```
1111111
1000001
1000001
1001001
1000001
1000001
1111111
```

- 每个 finder 外接 1 模块白分隔符，共占 8×8 模块。
- 三个 finder 合计固定 192 模块。占比：
  - N=21：43.5%
  - N=57：5.9%
  - N=197：0.5%

### 3.2 对齐图案（alignment）

- 仅 `N ≥ 33` 启用。
- 位于右下角：5×5 同心方环 + 1 模块白边，共占 7×7 模块。
- 中心坐标为 `(N-3.5, N-3.5)`，是摄像头单应变换的第四个锚点。
- 图案：

```
00000
01110
01010
01110
00000
```

（0 = 黑，1 = 白）

### 3.3 定时图案（timing）

- 第 6 行：列 `8..N-9` 黑白交替。
- 第 6 列：行 `8..N-9` 黑白交替。
- 用于模块尺寸估计、采样锁相和版本消歧。

### 3.4 格式带（format band）

- 格式 payload 按 5 bit 分块，每块用 **BCH(15,5,7)** 保护。
- 每块渲染为 **2 行 × 8 列**（15 个码字 bit + 1 个填充 bit）。
- 副本位置与数量按 `N` 自适应：

| N | 每副本块数 | payload | 副本位置 |
| --- | --- | --- | --- |
| `N < 33` | 1 | 5 bit | 右下角两份堆叠 |
| `33 ≤ N < 57` | 2 | 10 bit | 右上 + 左下 |
| `N ≥ 57` | 3 | 15 bit | 右上 + 左下 |

- payload 定义：

| 块数 | 字段 |
| --- | --- |
| 1 | layer 2 + ecc 2 + constraint 1 |
| 2 | layer 2 + ecc 2 + palette 2 + constraint 1 + seed 3 |
| 3 | layer 2 + ecc 2 + palette 2 + seed 6 + flags 3 |

- 解码端读取所有有效副本，按多数投票选择；没有多数则失败。
- `palette` 2 bit：bit1 = global/bucketed，bit0 = harmony。
- `flags` 3 bit：bit0 = constraint，bit1 = compressed，bit2 = encrypted。
- 小版本（`N < 33`）固定 `palette=bucketed`、`harmony=false`、`seed=0`。

### 3.5 校准枢纽（calibration hub）

- 居中放置，数据区排除。
- L1 不需要枢纽；L2/L3 使用灰阶 + 色板样本：

| 层 / N | 灰阶块 | 色板块 | 枢纽尺寸 |
| --- | --- | --- | --- |
| L2 | 4×4（16 灰） | 无 | 6×6 |
| L3a / `N < 33` | 4×4 | 4×4（16 样本） | 10×6 |
| L3a / `N ≥ 33` | 4×4 | 8×8（64 样本） | 14×10 |
| L3b / `N < 33` | 4×4 | 4×4（16 样本） | 10×6 |
| L3b / `33 ≤ N < 57` | 4×4 | 8×8（64 样本） | 14×10 |
| L3b / `N ≥ 57` | 4×4 | 16×16（256 样本） | 22×18 |

- 枢纽边框为黑白端点（角黑、边白），用于曝光缩放/偏移估计。
- 小版本的色板校准是抽样 + 最近样本，精度低于全色板。

### 3.6 数据区

- 所有未被功能图案占用的模块。
- 放置顺序：**Hilbert 曲线**（按 N 的 2 的幂网格生成后裁剪）。
- 数据区不包含静区、finder/分隔符、对齐图案、定时图案、格式带、校准枢纽。

## 4. 分层与符号映射

| 层 | 符号数 | 名义 bit/模块 | ECC 冗余 |
| --- | --- | --- | --- |
| L1 | 2 | 1 | 20% |
| L2 | 16 | 4 | 35% |
| L3a | 64 | 6 | 40% |
| L3b | 256 | 8 | 40% |

- L1：0 = 黑，1 = 白。
- L2：16 级等 L\* 灰，端点严格 0/255。
- L3a/L3b：前 16 项固定为同一组 L2 灰，保证索引嵌套。

## 5. 色板

### 5.1 bucketed（默认）

- 16 个等 L\* 亮度桶，桶中心 = L2 的 16 级灰。
- L3a：每桶 4 个色变体；L3b：每桶 16 个色变体。
- 桶内用 CIELAB max-min ΔE 贪心选点。
- 亮度分布均匀，最适合可逆邻差约束。

### 5.2 global（可选）

- 前 16 项仍是 L2 灰。
- 其余颜色在候选集上做全局 max-min ΔE 贪心。
- 色彩分离更好，但亮度分布不均匀，约束容量略高、约束质量略差。

### 5.3 候选集

- L3a：C/M/Y ∈ {0, 0.2, …, 1}，K ∈ {0, 0.15, …, 0.9} 的近似 CMYK 网格。
- L3b：sRGB 16 步网格 + 暗/亮 ramp。
- harmony：限制色相弧 ±60°，仅屏幕档使用，打印禁用。

## 6. 帧、白化、RS、BCH、CRC

### 6.1 帧格式

13 字节头：

| 字段 | 长度 |
| --- | --- |
| magic `"LC"` | 2 |
| frame version | 1 |
| layer id | 1 |
| flags | 1 |
| payload length | 4（大端） |
| payload CRC32 | 4（大端） |
| payload | 变长 |

帧后补零到 RS 数据容量。

### 6.2 白化

- xorshift32，种子来自格式带（0..63）。
- 白化在 RS 之前，作用于整个帧（含头、payload、补零）。

### 6.3 Reed-Solomon

- GF(256)，本原多项式 `0x11D`，生成元 2。
- 系统码，`n ≤ 255`。
- 按总符号数分块；每块 `parity = round(n × redundancy)`，`k = n - parity`。
- 块间 round-robin 交织。
- 解码：syndrome → Berlekamp-Massey → Chien → 线性方程求幅值 → 校验。

### 6.4 格式带 BCH

- BCH(15,5,7)，生成多项式 `x^10+x^8+x^5+x^4+x^2+x+1 = 0x537`。
- 解码用 32 个合法码字最近邻，可纠 3 bit。

### 6.5 CRC32

- IEEE 802.3，反射多项式 `0xEDB88320`，用于最终 payload 校验。

## 7. 可逆邻差约束

### 7.1 约束

- 16 个亮度 rank。
- 相邻模块（Hilbert 顺序）满足：

```
|rank(symbol_i) - rank(symbol_{i-1})| ≤ 8
```

### 7.2 编码

- 分块，默认 `m = 64` 模块。
- DP 计算合法序列数：

```
G[k][r] = 从 rank r 出发、长度 k 的合法续接数
T[m][r] = 从 rank r 出发、长度 m 的合法序列数
L[m]    = floor(log2(min_{r 有符号} T[m][r]))
```

- 每块承载固定 `L[m]` bit，用 BigInt 词典序 unranking。
- 首块起始 rank = 8；后续块起始 rank = 上一块最后一个符号的 rank。
- 最后不足 64 的块使用自己的 `L[rem]`。

### 7.3 容量

bucketed 色板下实测：

| 层 | 约束后 bit/模块 |
| --- | --- |
| L2 | ≈ 3.60 |
| L3a | ≈ 5.60 |
| L3b | ≈ 7.60 |

global L3b 约 7.75 bit/模块。

### 7.4 解码

- 严格模式：要求序列满足约束，否则失败。
- 宽容模式（参考实现默认用于解码）：对越界 rank 做贪心修正，再 ranking；残余错误交给 RS。
- **摄像头/强色偏场景建议生成 `constraint: off` 的码面**：约束码是数字信道特性，硬约束在强噪声下会放大符号错误。

## 8. 编码流程

```
payload
  → frame(header + CRC32)
  → 补零到 RS 数据容量
  → 白化
  → RS 分块编码 + 交织
  → bitstream
  → 邻差约束编码（可选）
  → 数据符号
  → 放入 Hilbert 数据区
  → 写格式带
  → 渲染模块 + 静区
  → PNG
```

---

## 9. 解码流程

### 9.1 Phase A：清洁/轴对齐

1. 灰度 + Otsu（双值图像回退到 min/max 中点）。
2. 行/列扫描 `1:2:1:2:1` finder 剖面。
3. 交叉验证 finder 中心，聚类，识别 TL/TR/BL。
4. 由中心距估计 `N`，计算原点与模块尺寸。
5. 读格式带（BCH + 多数投票）。
6. 建布局，采样数据模块。
7. 分类：L1 阈值；L2 灰阶 rank；L3 Lab 最近邻 + 仿射校准。
8. 约束解码 → 去交织 → RS → 去白化 → 帧校验 → payload。

### 9.2 Phase B：摄像头/透视

1. 阈值后做 8 连通域，找 ring-like 组件（finder 外环）。
2. 选三个最大 ring 作为 finder，识别 TL/TR/BL。
3. 对 `N ≥ 33`，在右下角附近找 5×5 对齐图案组件。
4. 用 finder 中心 + 对齐图案中心建立单应变换。
5. 用定时图案评分消歧版本 `N`。
6. 校验 finder + alignment 图案；失败时回退到暗像素四角单应。
7. 后续采样/格式/RS 同 Phase A。
8. 色板校准：
   - L2：16 灰块的实测 L\* 最近邻 rank。
   - L3：用色板样本拟合 3×4 仿射矩阵，再做 Lab 最近邻。
   - 清洁图像（平均 ΔE < 2.5）直接走 identity，避免过拟合。

## 10. 容量

### 10.1 公式

```
D = N² - 功能图案模块数
bits = D                                  (L1)
     = constrainedCapacity(D)             (L2/L3, constraint on)
     = D × bitsPerModule                  (constraint off)
S = floor(bits / 8)
RS 分块 → kTotal
payloadCapacity = kTotal - 13
```

### 10.2 实测

| 文本 | 字节 | 图像 | 版本/N | 模块 | 容量 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 心经 | 944 | 1024² | v8 / 49 | 19px | 1131B | OK |
| 心经 | 944 | 2048² | v10 / 57 | 32px | 1477B | OK |
| 金刚经 | 20406 | 1024² | v45 / 197 | 5px | 22635B | OK |
| 金刚经 | 20406 | 2048² | v45 / 197 | 10px | 22635B | OK |

> 金刚经在 2048² 下已经是接近实用摄像头密度的上限；需要更大余量时用 4096² 或分码。

## 11. Web / 摄像头

- Web 版位于 `docs/`，可直接把 GitHub Pages 源设为 `/docs`。
- `npm run build:web` 把浏览器兼容的 `src/` 复制到 `docs/lib/`（排除 Node-only 的 `png.js`）。
- `npm run web` 本地静态服务 `http://localhost:8080`。
- 摄像头需要 HTTPS 或 localhost。
- 编码面板支持 L1/L2/L3a/L3b、bucketed/global、fill/compact、512/1024/2048。
- 扫描面板支持：
  - 上传照片；
  - 摄像头实时预览；
  - 拍照识别；
  - 连续扫描（约 750ms 一次）。
- 摄像头模式建议使用 `constraint: off` + L3b + 2048²。

## 12. 已知限制与后续

1. **约束码在强色偏/噪声下脆弱**：摄像头模式默认关闭约束；后续可做 Viterbi/软判决约束解码。
2. **File Mode 未实现**：24bit 真彩数字承载模式待补。
3. **多帧/喷泉码未实现**：当前单帧解码。
4. **小版本无对齐图案**：`N < 33` 依赖三 finder + 暗角回退。
5. **小版本色板校准是抽样**：精度低于全色板。
6. **打印链路未实测**：L3a 是近似 CMYK 色域，真实打印需要逐机校准。
7. **不做 QR 兼容**：finder 比例 1:2:1:2:1，和 QR 的 1:1:3:1:1 明显区分；前端 App 先跑 LCC probe，再决定交给 LCC 还是 QR 解码器。
