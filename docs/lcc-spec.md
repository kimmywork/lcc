# LCC — Layered Chromatic Code 规范 v0.4

> 状态：参考实现。新层级按“信道鲁棒性 → 容量”排序；File Mode 独立。
> 代码：`src/`；Web 版：`docs/`；示例：`examples/`。

---

## 1. 层级

LCC 层名直接编码两个维度：

- `G<色彩位宽><符号位宽>`：灰度层；
- `C<色彩位宽><符号位宽>`：彩色层；
- 第一位是 `log2(色板大小)`，第二位是 `log2(符号数)`，`0` 表示无符号图案。

例如 `G13` = 黑白（1 bit）+ 8 符号（3 bit）= 4 bit/模块；`C55` = 32 色（5 bit）+ 32 符号（5 bit）= 10 bit/模块。

### 1.1 基础层（无符号图案）

| 层 | 符号表 | bit/模块 | ECC | 摄像头建议 |
| --- | --- | --- | --- | --- |
| **G10** | 2 态黑白 | 1 | 20% | **首选** |
| **G20** | 4 级等 L\* 灰 | 2 | 20% | **推荐** |
| **G30** | 8 级等 L\* 灰 | 3 | 30% | 受控拍摄 |
| **C40** | 16 色 max-min ΔE | 4 | 35% | **摄像头彩色首选** |
| **C50** | 32 色 max-min ΔE | 5 | 40% | 受控拍摄 |
| **C60** | 64 色 max-min ΔE | 6 | 40% | 清洁/数字/打印 |
| **C80** | 256 色 max-min ΔE | 8 | 40% | 清洁/数字/打印 |
| **File** | 24bit 真彩 | 24 | CRC32 | 纯数字，独立模式 |

- `G` 层是灰度轴；`C` 层使用 CIELAB max-min ΔE 色板。
- 彩色层不再强制包含灰度轴，以换取更大的最小 ΔE。
- 基础层使用 3-bit mode id；其余层使用 `mode=7` shape escape（见附录 A）。

### 1.2 色板最小 ΔE（实测）

| 层 | 最小 ΔE |
| --- | ---: |
| G20（4 灰） | 33.2 |
| G30（8 灰） | 14.2 |
| C40（16 色） | **48.8** |
| C50（32 色） | 35.7 |
| C60（64 色） | 25.0 |
| C80（256 色） | 13.7 |

> 决定摄像头鲁棒性的是最小两两 ΔE，不是平均 ΔE。16 色在三维色彩空间里可以比 16 灰更稳；64/256 色太密。

### 1.3 形状层（完整矩阵）

经典 8 形状为：空白、`/`、`\`、`X`、`+`、`-`、`|`、`□`，每个模块增加 3 bit。富形状层使用 32 个符号，增加 5 bit，符号表大小为 `|S| × |C|`。

32 符号由 6 组组成：
- 4 个 V 形角：`<`、`>`、`V`、`^`；
- 4 个中线箭头：`←`、`↑`、`→`、`↓`；
- 4 个对角线箭头：`↖`、`↗`、`↘`、`↙`；
- 4 个 1/4 方格块：`▘`、`▝`、`▖`、`▗`；
- 4 个中线 T：`┬`、`├`、`┤`、`┴`；
- 4 个对角线 T：一条完整对角线与另一条对角线的一半组合。

| 层 | 基础色板 | 符号 | bit/模块 | 建议 |
| --- | --- | ---: | ---: | --- |
| **C20** | 4 色 | 无 | 2 | 受控/数字 |
| **C23** | 4 色 | 8 | 5 | 受控/打印 |
| **C25** | 4 色 | 32 | 7 | 数字/打印，模块 ≥16 px |
| **C30** | 8 色 | 无 | 3 | 8 色基础层 |
| **C33** | 8 色 | 8 | 6 | 彩色摄像头首选 |
| **C35** | 8 色 | 32 | 8 | 数字/打印，模块 ≥16 px |
| **C40** | 16 色 | 无 | 4 | 摄像头彩色 |
| **C43** | 16 色 | 8 | 7 | `N≥25`，受控/打印 |
| **C45** | 16 色 | 32 | 9 | 数字/打印，模块 ≥16 px |
| **C50** | 32 色 | 无 | 5 | 受控拍摄 |
| **C53** | 32 色 | 8 | 8 | 数字/打印，模块 ≥16 px |
| **C55** | 32 色 | 32 | 10 | 数字/打印，模块 ≥16 px |
| **C60** | 64 色 | 无 | 6 | 清洁/数字/打印 |
| **C63** | 64 色 | 8 | 9 | 数字/打印，模块 ≥16 px |
| **C65** | 64 色 | 32 | 11 | 数字/打印，模块 ≥16 px |
| **C80** | 256 色 | 无 | 8 | 清洁数字/打印 |
| **C83** | 256 色 | 8 | 11 | 清洁数字/打印，`N≥33` |
| **C85** | 256 色 | 32 | 13 | 清洁数字/打印，`N≥33` |
| **G13** | 黑白 | 8 | 4 | 灰度摄像头 |
| **G15** | 黑白 | 32 | 6 | 数字/打印，模块 ≥16 px |
| **G23** | 4 灰 | 8 | 5 | 灰度摄像头/打印 |
| **G25** | 4 灰 | 32 | 7 | 数字/打印，模块 ≥16 px |
| **G30** | 8 灰 | 无 | 3 | 受控拍摄 |
| **G33** | 8 灰 | 8 | 6 | 受控拍摄/打印 |
| **G35** | 8 灰 | 32 | 8 | 数字/打印，模块 ≥16 px |

- 形状层使用 `mode=7` escape；具体层码见附录 A。
- 图案前景色：优先使用背景色的互补色；如果互补色与背景的 ΔE 太小（中灰），改用黑/白中对比度更高者。
- 形状层要求 `N≥25`；constraint bit 复用为 shape extension bit，因此 2 块格式即可表达。
- 8 形状层：4 px 模块不支持形状；摄像头最低建议 16 px，数字/打印至少 8–12 px。
- 32 形状层：模块最低 16 px；`C83/C85` 的校准枢纽更大，要求 `N≥33`。`fill` 模式不指定 `moduleSize` 时优先选更大模块。

## 2. 几何与动态尺寸

- 方形模块，边长 `s` 像素，整数；屏幕最小 4px，打印最小 6px。
- 版本 `v=1..100`，符号边长 `N = 21 + 4(v-1)`。
- 静区 `q=2`（屏幕）/ `4`（打印）。
- 绘制边长 `(N+2q)×s`。
- 选档：
  - **fill（默认）**：从最大 `s` 向下试，取能放下载荷的最大模块尺寸。
  - **compact**：选最小 `N`，再取最大 `s`，居中留白。
- 版本 `N` 不写入格式带，由 finder 中心距和定时图案推导。

## 3. 码面布局

### 3.1 定位图案

- 3 个：左上、右上、左下。
- 7×7 同心方环，剖面 `1:2:1:2:1`，外接 1 模块白分隔符。
- 三个 finder 固定 192 模块。占比：N=21 43.5%，N=57 5.9%，N=197 0.5%。

### 3.2 对齐图案

- `N≥25` 启用。
- 右下角 5×5 同心方环 + 1 模块白边，共 7×7。
- 中心 `(N-3.5, N-3.5)`，作为单应第四锚点。

### 3.3 定时图案

- 第 6 行列 `8..N-9` 黑白交替；第 6 列行 `8..N-9` 黑白交替。

### 3.4 格式带

- BCH(15,5,7)，每块 2 行 × 8 列（15 bit + 1 填充）。
- 副本：
  - `N<25`：右下角两份堆叠。
  - `N≥25`：右上 + 左下。
- payload：

| 块数 | 条件 | 字段 |
| --- | --- | --- |
| 1 | `N<25` | mode 3 + ecc 2 |
| 2 | `25≤N<57` | mode 3 + ecc 2 + constraint 1 + palette 2 + seed 2 |
| 3 | `N≥57` | mode 3 + ecc 2 + constraint 1 + palette 2 + seed 6 + flags 1 |

- `mode`：0=G10，1=G20，2=G30，3=C40，4=C50，5=C60，6=C80。
- `palette`：0=maxmin，1=harmony，2/3 保留。
- `flags`：1 bit 保留（压缩/加密由帧头表达）。
- 解码端读取所有有效副本，多数投票。

### 3.5 校准枢纽

- 居中，数据区排除。
- 灰度层：枢纽显示该层自身的 4/8 级灰（G20 4×4，G30 5×5），视觉与数据层一致。
- 彩色层：4×4 **16 级参考灰**（固定 RGB）+ 色板样本网格。

| 层 | 色板样本数 | 枢纽尺寸 |
| --- | --- | --- |
| G20 | 0 | 4×4 |
| G30 | 0 | 5×5 |
| C40 | 16（全） | 10×6 |
| C50 | N<33:16，否则 32 | 10×6 / 12×8 |
| C60 | N<33:16，33–56:32，≥57:64 | 10×6 / 12×8 / 14×10 |
| C80 | N<33:16，33–56:64，≥57:256 | 10×6 / 14×10 / 22×18 |

- 色板样本按 CIELAB 最远点采样选择，覆盖色相。
- 枢纽边框为黑白端点（角黑、边白）。

### 3.6 数据区

- 未被功能图案占用的模块。
- 放置顺序：Hilbert 曲线（按 N 的 2 的幂网格生成后裁剪）。

### 3.7 形状模式

- 每个数据模块 = 背景色 + 可选前景线图案。
- 8 种经典形态：`blank`、`/`、`\`、`X`、`+`、`-`、`|`、`□`。
- 32 种富形态：在经典 8 种上增加 V 形、中线箭头、对角线箭头、1/4 方格、中线 T、对角线 T。
- 中线箭头：横线/竖线贯穿整条中线；箭头由尖端所在的两个 1/4 方格的对角线组成。
- 对角线箭头：斜线贯穿整条对角线；箭头由尖端所在 1/4 方格的两条外边（原方格边的一半）组成。
- 线宽：`max(1px, round(s/8))`；图案内缩 `max(1px, round(s/16))`，避免相邻模块连线。
- `□` 使用内缩正方形，不使用模块边框。
- 前景色：`foregroundFor(background)` 在互补色、黑、白中选 ΔE 最大者。
- 格式：`mode=7`；`constraint` bit 复用为 `shapeExt`，`palette` 2 bit 作为 shape layer id，seed 低 2 bit 作为 shape variant。层码见附录 A。
- 校准枢纽增加 8 个形状参考 tile（黑底白线）和满墨颜色块。
- 解码：
  1. 模块内采样 8×8 或 12×12 子格；
  2. 2-means 分背景/前景；
  3. 多数簇 = 背景色 → 色板分类；
  4. 少数簇 = 前景掩码 → 8/32 形状模板匹配（允许 ±1 子格平移）；
  5. 用形状模板膨胀后的背景区域重新估计背景色，减少模糊污染。

## 4. 色板

### 4.1 灰度层

- G10：2 态黑白。
- G20：4 级等 L\* 灰（0/33/67/100）。
- G30：8 级等 L\* 灰。
- 端点严格 0/255。

### 4.2 彩色层

- 候选集：sRGB 网格 + 暗/亮 ramp。
- 种子：黑、白。
- 贪心 max-min CIELAB ΔE，选到目标色数。
- 色数：4、8、16、32、64、256；每个色数都提供无符号/8 符号/32 符号三种形状配置。
- harmony：限制色相弧 ±60°，仅屏幕档可选；形状层第一版固定 maxmin。

## 5. 帧、白化、RS、BCH、CRC

- 帧头 13 字节：magic `"LC"`、version、layer id、flags、payload length、CRC32。
- 白化：xorshift32，seed 来自格式带。
- RS(GF(256))：`0x11D`，生成元 2，系统码，`n≤255`，块间交织。
- ECC 级：`L=20%`、`M=30%`、`Q=35%`、`H=40%`；格式带 2 bit ecc 字段。
- Boost ECC：同一版本内从 H 向下尝试，选能放下载荷的最高 ECC。
- 格式带 BCH(15,5,7)，解码用 32 码字最近邻。
- 最终 CRC32 校验。

---

## 6. 可逆邻差约束

- 灰度层：rank 数 = 灰阶数（4/8），`maxDiff = floor(rankCount/2)`。
- 彩色层：16 个亮度 rank，`maxDiff = 8`。
- 分块 `m=64`，DP + BigInt 枚举编码。
- 首块起始 rank = 中间 rank；后续块用上一块最后一个符号的 rank。
- 每块固定 `L[m] = floor(log2(min_r T[m][r]))` bit。
- 解码：
  - 严格模式要求合法序列。
  - 宽容模式做贪心修正；Viterbi 用颜色/灰阶代价找最可能的合法序列。
- 摄像头建议关闭 constraint；清洁数字码可开启。

## 7. 编码流程

编码选项：`layer`、`paletteMode`、`eccLevel`（auto/L/M/Q/H）、`boostEcc`、`minVersion`/`maxVersion`、`moduleSize`、`quietZone`、`constraint`、`seed`。
输出：PNG（Canvas/Node）或 SVG（矢量，适合打印）。

```
payload
  → frame(header + CRC32)
  → 补零到 RS 数据容量
  → 白化
  → RS 分块编码 + 交织
  → bitstream
  → 邻差约束编码（可选）
  → 数据符号（形状层：shape×C + color）
  → Hilbert 数据区
  → 写格式带（形状层 mode=7）
  → 渲染（固定色 + 数据色板 + 形状前景）
  → PNG / SVG
```

## 8. 解码流程

### 8.1 QR 式预处理

- 灰度：Otsu、Otsu+闭运算、Bradley 自适应（1/8、1/16、1/4）+ 闭运算。
- V 通道（max(R,G,B)）：Otsu/自适应 + 饱和度过滤（`sat<0.5 || V<80`），防止彩色数据与 finder 环粘连。
- 按顺序重试，任一变体通过 CRC 即返回。
- 摄像头优先 V 通道 + 透视；清洁图优先 Otsu + 轴对齐。

### 8.2 检测

- 轴对齐：行/列 `1:2:1:2:1` 扫描。
- 透视：8 连通域找 ring-like 组件；径向检查 `1.75s` 白 / `3.2s` 黑，方向无关。
- 三 finder + `N≥25` 对齐图案 → 四锚点单应。
- 定时图案评分消歧版本 N。
- 采样：模块内 3×3 canonical 子网格取中值。

### 8.3 校准与分类

- 光照：finder/alignment 的黑白模块内部取中值，三个通道始终按 `(channel-black)/(white-black)*255` 归一化，再用双线性场跟光照起伏。几何检测仍用 V 通道，不先改整张图。
- 形状层：模块按子格积分采样。形状是亮度残差和八个已知模板的归一化相关；模块短边小于 12 像素时先做一次锐化。有笔画时，颜色取模板以外的像素；没有笔画时，颜色取占多数的亮度。
- G10：阈值。
- 灰度层：16 级参考灰的实测 L\* → 名义 L\* 分段映射，再分类到 4/8 级灰。
- 彩色层：色板样本拟合 3×4 仿射，Lab 最近邻。
- 形状层：模块内 2-means 分背景/前景；背景簇中值 + 校准器分类颜色；前景掩码做 8/32 形状模板匹配（±1 子格平移）；形状确定后用膨胀掩码重新估计背景色。
- 清洁图像（平均 ΔE < 2.5）走 identity，避免过拟合。
- 可选局部 rank（默认关闭，实验项）。

### 8.4 约束/RS/CRC

- 约束解码 → 去交织 → RS → 去白化 → 帧校验 → payload。

### 8.5 多帧叠加

- 摄像头可捕获 1/3/5 帧；每帧独立检测。
- 按 `version/N` 分组，选择帧数最多的组；把每帧投影到统一的 canonical 模块网格（`s=12..24px`，静区 4），逐像素平均。
- 平均降低随机噪声/传感器噪声/压缩噪声；随机噪声增益约 `√N`。
- 定位标记负责中性色偏（各通道增益和黑电平）。不修复运动模糊和失焦；要求码面基本静止。
- 动画/多帧码不能直接平均不同 payload 的帧；必须按帧 ID 分组。
- 统计面板显示叠加帧数、canonical 模块尺寸和帧间 σ；最终由 RS + CRC 校验。
- 后续：逐模块方差 → erasure/软判决；跨帧跟踪/运动补偿。

## 9. 容量

```
D = N² - 功能图案模块数
bits = D                                  (G10)
     = constrainedCapacity(D)             (灰度/彩色, constraint on)
     = D × bitsPerModule                  (constraint off)
     = D × log2(|S| × |C|)                (形状层, S=形状数, C=背景色数)
S = floor(bits / 8)
RS 分块 → kTotal
payloadCapacity = kTotal - 13
```

## 10. 摄像头建议

- **首选**：G10、G20、C30、C40、C33。
- **受控**：G30、C50、G13、G23；避开屏幕高光/强反光。
- **C43**：受控/打印，`N≥25`，模块最低建议 16 px；小载荷时自动选更大模块。
- **清洁/数字/打印**：C60、C80，以及所有 32 符号层。
- 形状层需要更大模块：4 px 只适合纯颜色层，摄像头建议 16 px。
- 摄像头关闭 constraint。
- 手机摄像头需要 HTTPS 或 localhost，并且需要用户点击授权；`http://192.168.x.x` 不是安全上下文，Safari/Chrome 会禁用摄像头。
- 打开失败时按 1920×1080 → 1280×720 → environment → 默认摄像头回退。
- 多帧叠加建议 3 帧；码面静止时降低随机噪声。中性色偏由定位标记矫正，不由多帧平均修复。不修复运动模糊和失焦。
- 多级灰/彩在强反光/高光削顶下仍可能丢级；这是多级量化问题，不是 finder 检测问题。
- QR 是二值码；它的预处理不能直接解决多级灰/彩的量化问题。

## 11. 已知限制

1. G30/C50 在强反光/高光削顶下仍可能失败。
2. C60/C80 和 32 符号层面向清洁/数字/打印，不建议随手拍。
3. File Mode（24bit）尚未实现。
4. 形状层已实现完整的 `G/C × 色数 × 0/8/32 符号` 矩阵，但真实相机/打印 benchmark 尚未完成；4 px 模块不支持形状，摄像头建议 16 px。
5. `C43`（16 色 + 8 符号，7 bit）需要 `N≥25`；`C83/C85`（256 色 + 8/32 符号）需要 `N≥33`。32 符号层面向数字/打印/受控拍摄，不建议手机随手拍。
6. 多帧/喷泉码尚未实现。
7. 打印链路未实测；真实打印需要逐机校准。
8. 不做 QR 兼容；finder 比例 `1:2:1:2:1`。

## 附录 A：格式带 bit 布局

### 1 块（N<25）

```
bit 0..2  mode
bit 3..4  ecc
```

### 2 块（25≤N<57）

```
bit 0..2  mode
bit 3..4  ecc
bit 5     constraint
bit 6..7  palette
bit 8..9  seed (2 bit)
```

### 3 块（N≥57）

```
bit 0..2   mode
bit 3..4   ecc
bit 5      constraint
bit 6..7   palette
bit 8..13  seed (6 bit)
bit 14     flags (reserved)
```

### 形状层（mode=7）

形状层的 `constraint` 恒为 0，该 bit 复用为 `shapeExt`；2 块和 3 块格式都适用。层码为 `(shapeExt, palette, seed低2位)`：

| 层码 | 层 | 层码 | 层 |
| --- | --- | --- | --- |
| (0,0,0) | C30 | (1,0,0) | C55 |
| (0,1,0) | G13 | (1,0,1) | G15 |
| (0,2,0) | G23 | (1,0,2) | G35 |
| (0,2,1) | G33 | (1,0,3) | G25 |
| (0,3,0) | C33 | (1,1,0) | C65 |
| (0,3,1) | C35 | (1,1,1) | C20 |
| (1,2,0) | C85 | (1,1,2) | C23 |
| (1,2,1) | C53 | (1,1,3) | C25 |
| (1,2,2) | C63 | (1,3,0) | C43 |
| (1,2,3) | C83 | (1,3,1) | C45 |

形状层固定使用白化 seed 0；`seed` 字段只承载 variant。旧版本以非零 seed 写出的形状码不再兼容，需要重新生成。
