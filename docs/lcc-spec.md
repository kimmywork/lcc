# LCC — Layered Chromatic Code 规范 v0.4

> 状态：参考实现。新层级按“信道鲁棒性 → 容量”排序；File Mode 独立。
> 代码：`src/`；Web 版：`docs/`；示例：`examples/`。

---

## 1. 层级

| 层 | 符号表 | bit/模块 | ECC | 摄像头建议 |
| --- | --- | --- | --- | --- |
| **L1** | 2 态黑白 | 1 | 20% | **首选** |
| **L2a** | 4 级等 L\* 灰 | 2 | 20% | **推荐** |
| **L2b** | 8 级等 L\* 灰 | 3 | 30% | 受控拍摄 |
| **L3c** | 16 色 max-min ΔE | 4 | 35% | **摄像头彩色首选** |
| **L3d** | 32 色 max-min ΔE | 5 | 40% | 受控拍摄 |
| **L4e** | 64 色 max-min ΔE | 6 | 40% | 清洁/数字/打印 |
| **L4f** | 256 色 max-min ΔE | 8 | 40% | 清洁/数字/打印 |
| **File** | 24bit 真彩 | 24 | CRC32 | 纯数字，独立模式 |

- L1/L2a/L2b 是灰度轴；L3b/L3c/L3d/L4e/L4f 是 CIELAB max-min ΔE 色板。
- 彩色层不再强制包含 L2 的灰阶，以换取更大的最小 ΔE。
- 形状层 L1s/L2s/L3s/L3t 在基础色板上叠加 8 种线形态，见 1.2。
- File Mode 不属于分层表，后续单独实现。

### 1.1 色板最小 ΔE（实测）

| 层 | 最小 ΔE |
| --- | ---: |
| L2a（4 灰） | 33.2 |
| L2b（8 灰） | 14.2 |
| L3c（16 色） | **48.8** |
| L3d（32 色） | 35.7 |
| L4e（64 色） | 25.0 |
| L4f（256 色） | 13.7 |

> 决定摄像头鲁棒性的是最小两两 ΔE，不是平均 ΔE。16 色在三维色彩空间里可以比 16 灰更稳；64/256 色太密。

### 1.2 形状层（1–7 bit 阶梯）

形状层在基础色板上叠加 8 种线形态之一：空白、`/`、`\`、`X`、`+`、`-`、`|`、`□`。每个模块增加 3 bit，符号表大小为 `|S| × |C|`。

| 层 | 基础色板 | 形状 | bit/模块 | 备注 |
| --- | --- | ---: | ---: | --- |
| L3b | 8 色 | 1（无图案） | 3 | 8 色基础层 |
| L1s | 黑白 | 8 | 4 | 灰度摄像头 |
| L2s | 4 灰 | 8 | 5 | 灰度摄像头/打印 |
| L3s | 8 色 | 8 | 6 | 彩色摄像头首选 |
| L3t | 16 色 | 8 | 7 | `N≥25`，受控/打印 |

- 形状层使用 `mode=7` escape，`palette` 2 bit 作为 shape layer id。
- 图案前景色：优先使用背景色的互补色；如果互补色与背景的 ΔE 太小（中灰），改用黑/白中对比度更高者。
- 形状层要求 `N≥25`；L3t 用 constraint bit 作为 shape extension bit，因此 2 块格式即可表达，不要求 `N≥57`。
- 4 px 模块不支持形状；摄像头最低建议 16 px，数字/打印至少 8–12 px。`fill` 模式不指定 `moduleSize` 时优先选更大模块。

## 2. 几何与动态尺寸

- 方形模块，边长 `s` 像素，整数；屏幕最小 4px，打印最小 6px。
- 版本 `v=1..100`，符号边长 `N = 21 + 4(v-1)`。
- 静区 `q=2`（屏幕）/ `4`（打印）。
- 绘制边长 `(N+2q)×s`。
- 选档：
  - **fill（默认）**：从最大 `s` 向下试，取能放下载荷的最大模块尺寸。
  - **compact**：选最小 `N`，再取最大 `s`，居中留白。
- 版本 `N` 不写入格式带，由 finder 中心距和定时图案推导。

## 3. 码面布局

### 3.1 定位图案

- 3 个：左上、右上、左下。
- 7×7 同心方环，剖面 `1:2:1:2:1`，外接 1 模块白分隔符。
- 三个 finder 固定 192 模块。占比：N=21 43.5%，N=57 5.9%，N=197 0.5%。

### 3.2 对齐图案

- `N≥25` 启用。
- 右下角 5×5 同心方环 + 1 模块白边，共 7×7。
- 中心 `(N-3.5, N-3.5)`，作为单应第四锚点。

### 3.3 定时图案

- 第 6 行列 `8..N-9` 黑白交替；第 6 列行 `8..N-9` 黑白交替。

### 3.4 格式带

- BCH(15,5,7)，每块 2 行 × 8 列（15 bit + 1 填充）。
- 副本：
  - `N<25`：右下角两份堆叠。
  - `N≥25`：右上 + 左下。
- payload：

| 块数 | 条件 | 字段 |
| --- | --- | --- |
| 1 | `N<25` | mode 3 + ecc 2 |
| 2 | `25≤N<57` | mode 3 + ecc 2 + constraint 1 + palette 2 + seed 2 |
| 3 | `N≥57` | mode 3 + ecc 2 + constraint 1 + palette 2 + seed 6 + flags 1 |

- `mode`：0=L1，1=L2a，2=L2b，3=L3c，4=L3d，5=L4e，6=L4f。
- `palette`：0=maxmin，1=harmony，2/3 保留。
- `flags`：1 bit 保留（压缩/加密由帧头表达）。
- 解码端读取所有有效副本，多数投票。

### 3.5 校准枢纽

- 居中，数据区排除。
- 灰度层：枢纽显示该层自身的 4/8 级灰（L2a 4×4，L2b 5×5），视觉与数据层一致。
- 彩色层：4×4 **16 级参考灰**（固定 RGB）+ 色板样本网格。

| 层 | 色板样本数 | 枢纽尺寸 |
| --- | --- | --- |
| L2a | 0 | 4×4 |
| L2b | 0 | 5×5 |
| L3c | 16（全） | 10×6 |
| L3d | N<33:16，否则 32 | 10×6 / 12×8 |
| L4e | N<33:16，33–56:32，≥57:64 | 10×6 / 12×8 / 14×10 |
| L4f | N<33:16，33–56:64，≥57:256 | 10×6 / 14×10 / 22×18 |

- 色板样本按 CIELAB 最远点采样选择，覆盖色相。
- 枢纽边框为黑白端点（角黑、边白）。

### 3.6 数据区

- 未被功能图案占用的模块。
- 放置顺序：Hilbert 曲线（按 N 的 2 的幂网格生成后裁剪）。

### 3.7 形状模式

- 每个数据模块 = 背景色 + 可选前景线图案。
- 8 种形态：`blank`、`/`、`\`、`X`、`+`、`-`、`|`、`□`。
- 线宽：`max(1px, round(s/8))`；图案内缩 `max(1px, round(s/16))`，避免相邻模块连线。
- `□` 使用内缩正方形，不使用模块边框。
- 前景色：`foregroundFor(background)` 在互补色、黑、白中选 ΔE 最大者。
- 格式：`mode=7` + `palette` 2 bit 作为 shape layer id；constraint bit 复用为 shapeExt，因此 L3t 在 2 块格式（`N≥25`）即可表达。
- 校准枢纽增加 8 个形状参考 tile（黑底白线）和满墨颜色块。
- 解码：
  1. 模块内采样 8×8 或 12×12 子格；
  2. 2-means 分背景/前景；
  3. 多数簇 = 背景色 → 色板分类；
  4. 少数簇 = 前景掩码 → 8 形状模板匹配（允许 ±1 子格平移）；
  5. 用形状模板膨胀后的背景区域重新估计背景色，减少模糊污染。

## 4. 色板

### 4.1 灰度层

- L1：2 态黑白。
- L2a：4 级等 L\* 灰（0/33/67/100）。
- L2b：8 级等 L\* 灰。
- 端点严格 0/255。

### 4.2 彩色层

- 候选集：sRGB 网格 + 暗/亮 ramp。
- 种子：黑、白。
- 贪心 max-min CIELAB ΔE，选到目标色数。
- 色数：L3b 8，L3c 16，L3d 32，L4e 64，L4f 256；形状层 L3s 8、L3t 16。
- harmony：限制色相弧 ±60°，仅屏幕档可选；形状层第一版固定 maxmin。

## 5. 帧、白化、RS、BCH、CRC

- 帧头 13 字节：magic `"LC"`、version、layer id、flags、payload length、CRC32。
- 白化：xorshift32，seed 来自格式带。
- RS(GF(256))：`0x11D`，生成元 2，系统码，`n≤255`，块间交织。
- ECC 级：`L=20%`、`M=30%`、`Q=35%`、`H=40%`；格式带 2 bit ecc 字段。
- Boost ECC：同一版本内从 H 向下尝试，选能放下载荷的最高 ECC。
- 格式带 BCH(15,5,7)，解码用 32 码字最近邻。
- 最终 CRC32 校验。

---

## 6. 可逆邻差约束

- 灰度层：rank 数 = 灰阶数（4/8），`maxDiff = floor(rankCount/2)`。
- 彩色层：16 个亮度 rank，`maxDiff = 8`。
- 分块 `m=64`，DP + BigInt 枚举编码。
- 首块起始 rank = 中间 rank；后续块用上一块最后一个符号的 rank。
- 每块固定 `L[m] = floor(log2(min_r T[m][r]))` bit。
- 解码：
  - 严格模式要求合法序列。
  - 宽容模式做贪心修正；Viterbi 用颜色/灰阶代价找最可能的合法序列。
- 摄像头建议关闭 constraint；清洁数字码可开启。

## 7. 编码流程

编码选项：`layer`、`paletteMode`、`eccLevel`（auto/L/M/Q/H）、`boostEcc`、`minVersion`/`maxVersion`、`moduleSize`、`quietZone`、`constraint`、`seed`。
输出：PNG（Canvas/Node）或 SVG（矢量，适合打印）。

```
payload
  → frame(header + CRC32)
  → 补零到 RS 数据容量
  → 白化
  → RS 分块编码 + 交织
  → bitstream
  → 邻差约束编码（可选）
  → 数据符号（形状层：shape×C + color）
  → Hilbert 数据区
  → 写格式带（形状层 mode=7）
  → 渲染（固定色 + 数据色板 + 形状前景）
  → PNG / SVG
```

## 8. 解码流程

### 8.1 QR 式预处理

- 灰度：Otsu、Otsu+闭运算、Bradley 自适应（1/8、1/16、1/4）+ 闭运算。
- V 通道（max(R,G,B)）：Otsu/自适应 + 饱和度过滤（`sat<0.5 || V<80`），防止彩色数据与 finder 环粘连。
- 按顺序重试，任一变体通过 CRC 即返回。
- 摄像头优先 V 通道 + 透视；清洁图优先 Otsu + 轴对齐。

### 8.2 检测

- 轴对齐：行/列 `1:2:1:2:1` 扫描。
- 透视：8 连通域找 ring-like 组件；径向检查 `1.75s` 白 / `3.2s` 黑，方向无关。
- 三 finder + `N≥25` 对齐图案 → 四锚点单应。
- 定时图案评分消歧版本 N。
- 采样：模块内 3×3 canonical 子网格取中值。

### 8.3 校准与分类

- 光照：finder/alignment 已知黑/白拟合双线性 black/white 场，归一化 `(rgb-black)/(white-black)`。
- L1：阈值。
- 灰度层：16 级参考灰的实测 L\* → 名义 L\* 分段映射，再分类到 4/8 级灰。
- 彩色层：色板样本拟合 3×4 仿射，Lab 最近邻。
- 形状层：模块内 2-means 分背景/前景；背景簇中值 + 校准器分类颜色；前景掩码做 8 形状模板匹配（±1 子格平移）；形状确定后用膨胀掩码重新估计背景色。
- 清洁图像（平均 ΔE < 2.5）走 identity，避免过拟合。
- 可选局部 rank（默认关闭，实验项）。

### 8.4 约束/RS/CRC

- 约束解码 → 去交织 → RS → 去白化 → 帧校验 → payload。

### 8.5 多帧叠加

- 摄像头可捕获 1/3/5 帧；每帧独立检测。
- 按 `version/N` 分组，选择帧数最多的组；把每帧投影到统一的 canonical 模块网格（`s=12..24px`，静区 4），逐像素平均。
- 平均降低随机噪声/传感器噪声/压缩噪声；随机噪声增益约 `√N`。
- 不修复运动模糊、失焦、系统性色偏；要求码面基本静止。
- 动画/多帧码不能直接平均不同 payload 的帧；必须按帧 ID 分组。
- 统计面板显示叠加帧数、canonical 模块尺寸和帧间 σ；最终由 RS + CRC 校验。
- 后续：逐模块方差 → erasure/软判决；跨帧跟踪/运动补偿。

## 9. 容量

```
D = N² - 功能图案模块数
bits = D                                  (L1)
     = constrainedCapacity(D)             (灰度/彩色, constraint on)
     = D × bitsPerModule                  (constraint off)
     = D × log2(|S| × |C|)                (形状层, S=形状数, C=背景色数)
S = floor(bits / 8)
RS 分块 → kTotal
payloadCapacity = kTotal - 13
```

## 10. 摄像头建议

- **首选**：L1、L2a、L3b、L3c、L3s。
- **受控**：L2b、L3d、L1s、L2s；避开屏幕高光/强反光。
- **L3t**：受控/打印，`N≥25`，模块最低建议 16 px；小载荷时自动选更大模块。
- **清洁/数字/打印**：L4e、L4f。
- 形状层需要更大模块：4 px 只适合纯颜色层，摄像头建议 16 px。
- 摄像头关闭 constraint。
- 手机摄像头需要 HTTPS 或 localhost，并且需要用户点击授权；`http://192.168.x.x` 不是安全上下文，Safari/Chrome 会禁用摄像头。
- 打开失败时按 1920×1080 → 1280×720 → environment → 默认摄像头回退。
- 多帧叠加建议 3 帧；码面静止时降低随机噪声，不修复运动模糊/系统性色偏。
- 多级灰/彩在强反光/高光削顶下仍可能丢级；这是多级量化问题，不是 finder 检测问题。
- QR 是二值码；它的预处理不能直接解决多级灰/彩的量化问题。

---

## 11. 已知限制

1. L2b/L3d 在强反光/高光削顶下仍可能失败。
2. L4e/L4f 面向清洁/数字/打印，不建议随手拍。
3. File Mode（24bit）尚未实现。
4. 形状层已实现（L3b/L1s/L2s/L3s/L3t），但真实相机/打印 benchmark 尚未完成；4 px 模块不支持形状，摄像头建议 16 px。
5. L3t（16 色 + 8 形态，7 bit）需要 `N≥25`；小载荷会自动用大模块，大载荷时才降到 16 px 左右。
6. 多帧/喷泉码尚未实现。
7. 打印链路未实测；真实打印需要逐机校准。
8. 不做 QR 兼容；finder 比例 `1:2:1:2:1`。

## 附录 A：格式带 bit 布局

### 1 块（N<25）

```
bit 0..2  mode
bit 3..4  ecc
```

### 2 块（25≤N<57）

```
bit 0..2  mode
bit 3..4  ecc
bit 5     constraint
bit 6..7  palette
bit 8..9  seed (2 bit)
```

### 3 块（N≥57）

```
bit 0..2   mode
bit 3..4   ecc
bit 5      constraint
bit 6..7   palette
bit 8..13  seed (6 bit)
bit 14     flags (reserved)
```

### 形状层（mode=7）

形状层的 `constraint` 恒为 0，该 bit 复用为 `shapeExt`；2 块和 3 块格式都适用。

```
mode = 7
palette 0 = L3b（8 色，无图案）
palette 1 = L1s（黑白 + 8 形态）
palette 2 = L2s（4 灰 + 8 形态）
palette 3 = L3s（8 色 + 8 形态）
palette 3 + shapeExt=1 = L3t（16 色 + 8 形态）
```
